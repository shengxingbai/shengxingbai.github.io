## 同步到 GitHub 并公网发布（PAT 方式）
- 用户站点仓库 `shengxingbai/shengxingbai.github.io`（用户已在 GitHub 网页手动创建，默认分支 main）。
- **关键坑：GitHub 连接器是只读集成（integration），读可行但写/建仓/推文件均返回 403 "Resource not accessible by integration"。** 推送代码必须用 Personal Access Token（PAT）走 `git push`，不能用连接器 `push_files`。
- 推送流程（已在本地 main 分支验证可用）：
  1. `git remote set-url origin https://<PAT>@github.com/shengxingbai/shengxingbai.github.io.git`
  2. `git push -u origin main`
  3. `git remote set-url origin https://github.com/shengxingbai/shengxingbai.github.io.git`  # 立即移除地址中的 token
- **Pages 开启可用 GitHub REST API 直接做**（无需手动点）：`POST /repos/{owner}/{repo}/pages` body `{"source":{"branch":"main","path":"/"}}`（需 token；409 表示已启用）。
- 公网测试用 `curl -s -o /dev/null -w "%{http_code}" https://shengxingbai.github.io/...`。沙箱 /tmp 不可写，curl 输出落到工作目录。
- **固定链接坑**：Jekyll 默认文章 permalink 含 `:categories` 段（如 `/随笔/2024/01/15/welcome.html`）；`permalink: pretty` 还会把页面变目录式 `/resume/`（与 `.html` 链接冲突 404）。最终采用 `permalink: /:year/:month/:day/:title.html`：页面落到 `/resume.html`，文章落到 `/2024/01/15/welcome.html`（无分类段，最规整）。
- 安全：PAT 曾在对话中以明文提供，已用完即移除远程地址中的 token；建议用户在 GitHub 撤销/轮换该令牌。
