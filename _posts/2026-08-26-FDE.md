## 第 1 章 FDE 的崛起

> 「给间谍做软件最大的挑战是：我不认识任何间谍。」——鲍勃·麦格鲁，Palantir 早期高管

### 1.1 先看一个"死掉的项目"长什么样

- 一个典型失败剧本：**演示惊艳 → 高管拍板 → 签约 → 交付 → 无人使用 → 项目安静死亡**。合同每一项都完成了，钱也付了，唯一没到货的是"价值"。
- 麻省理工学院 2025 年报告的著名结论：企业烧掉的三四百亿美元人工智能投入里，**95% 没有产生可衡量的财务回报**。
- 失败原因**不是模型不够聪明**，而是系统"不记反馈、不存上下文、不进工作流"——长得像产品，用起来像展品。
- 一个形象的对照：年轻创业公司只挑一个痛点打穿、绑定真实用户，一年做到两千万美元收入；大公司想一口吃成胖子，结果全军覆没。
- 问题的根源是一堵墙：**造软件的地方，和价值产生的地方，不在一个地方**。需求被工单、纪要、周报层层转述，每转一次丢一层信息。

### 1.2 Palantir 的胜利：FDE 的诞生故事

- 2003 年 Palantir 给美国情报机构做数据分析软件，遇到死结：**保密单位没法做用户访谈**（你既接触不到间谍，间谍也不会告诉你他怎么工作）。
- 联合创始人科恩的笨办法——"演示循环"：
  1. 先做个演示样品送上门；
  2. 被骂"这东西太糟了"；
  3. 追问"那你们希望它哪里不一样"；
  4. 一条条记下来，回去改，改完再送上门。
- 这个循环里藏着 FDE 的两个原始直觉：
  - **复杂领域的客户，在看到能用的东西之前，不知道自己要什么**；
  - **想知道客户要什么，最快的路是让造东西的人站到用东西的人旁边**。
- 第 13 号员工桑卡尔（FDE 战略真正的发明者）的两个关键动作：
  - 做一个可灵活定制的平台，然后**派工程师驻扎客户现场**修完"最后一公里"；
  - **改账本**：把"为单个客户做定制"从"服务成本"重新定义为"产品发现"——现场踩的每个坑，都是平台下一次进化的路标。
- 桑卡尔本人的原型现场：在保密信息室联合办公两周，用松紧带把电话绑在头上（保密室禁用免提），每天 19 小时，一边听分析师提意见一边改代码。
- 战场上的实战案例：驻场工程师发现士兵只要"在地图上标出这条路可疑"的小工具，当场拼出来——这个工具救了命，后来成为平台标准功能。**它不可能诞生在任何总部的会议室里**。
- 商业转折点（空客案例）：A380 燃油泵故障空客自查两年无果，Palantir 进场接传感器数据，**两周破案**（飞机爬升时燃油晃离泵体），保住据报道价值数百亿美元的订单。
- 长期结果验证：到 2016 年，Palantir 的前置部署工程师人数**超过了**传统产品工程师；2025 年第四季度净收入留存（老客户自动多付钱的比例）达 139%，市值一度突破 4000 亿美元。

### 1.3 FDE 的定义：是什么、不是什么

**一句话定义**：

> 前置部署工程师，是一个驻扎在客户现场、填补"产品能做的事"与"客户需要的事"之间鸿沟的工程师。

拆开理解这五个词：

- **驻扎现场**：不一定是天天坐客户办公室，而是"工作语境的嵌入"——进客户的群、读客户的数据、开客户的会、认识那个"知道流程为什么是这样"的人。
- **鸿沟**：产品开箱即用的地方不需要 FDE；鸿沟越深的地方（情报、金融、制造、医疗、法律）FDE 越多。
- **工程师**：写生产环境的代码，不是写报告——这个岗位的底线是"这不是咨询岗"。
- **Forward Deployed（前置部署）**：军事术语，指部署在前线的部队——把最有战斗力的人放在离问题最近的地方。

**用排除法理解（它不是什么）**——这部分非常重要：

| 容易混淆的角色 | 区别 |
| --- | --- |
| **不是售前** | 售前在签约前结束，目标是赢单，作品是幻灯片；FDE 在签约后才进入深水区，目标是赢结果，作品是跑在生产环境里的系统 |
| **不是驻场外包** | 驻场按工时结算、从零现写、人走系统停；FDE 按阶段交付按结果验收、带着产品底座来做、做完会走且能力沉淀在客户团队里。一句话：驻场卖人头，FDE 卖结果 |
| **不是咨询顾问** | 顾问交付建议、不对执行负责；FDE 对系统最终运转负责，终点是"客户团队能独立使用"。顾问希望你一直需要他，FDE 希望你迟早不需要他 |
| **不是传统产品工程师** | 产品工程师面对抽象用户（画像、漏斗、日活）；FDE 面对具体客户（某银行风控部、某个农场、某支巡逻队） |

**为什么 2025 年才爆发**：

- 生成式人工智能制造了前所未有的落差：**做出惊艳演示只要五分钟，把演示接进企业真实的数据、权限、合规和工作流，难度高一个数量级**。
- 行业的共识变成：接下来的胜负手不是模型质量，是部署能力。
- 硬数据：FDE 岗位发布量九个月涨八倍；OpenAI 的 FDE 团队一年从 2 人到 52 人；Salesforce 承诺招 1000 名；连德勤都成立了 FDE 业务线。
- 最深的原因：**人工智能智能体是个"没有在位者的新品类"**——没人知道它该长什么样，包括客户自己，答案只能去客户现场找。

### 1.4 FDE 需要什么能力和特质（三层特质）

1. **足够宽的技术通才**：写得了代码、调得了接口、懂数据管道、能上云、摸得准大模型的脾气、懂企业环境的"水电煤"（单点登录、权限、合规认证）。
2. **把技术翻译成业务结果的能力**（与普通工程师的分水岭）：
   - 普通面试满分答案："我把查询优化了 40%。"
   - FDE 面试满分答案："我把查询优化了 40%，这让客户的分析师每天提前两小时拿到报表，团队处理容量翻了三倍。"
   - **技术成就必须换算成客户语言，才算答完。**
3. **主人翁意识加一点叛逆**：
   - 圈内流传的岗位信条："部署在凌晨两点挂了。你不提工单，不怪别的团队，不回去睡觉。你修好它。句号。"
   - Palantir 期待"领域叛逆者"：看得出客户现状的荒谬之处，敢推动十倍级而不是一成级的改变。
   - CEO 卡普定的行为标杆是"法国侍者"：嵌在服务流程里、对真实需求敏感，同时有足够自信与品位，把客户从"他们以为自己要的"引导到"真正对他们好的"。

**FDE 的一天怎么过**（时间分配参考）：

- 40%–50%：泡在客户侧写代码调系统；
- 20%–30%：和客户管理层对齐方向、拆问题、做架构决策；
- 10%–20%：把现场学到的模式沉淀回公司产品线；
- 剩余：评估优化、写打法手册、培训客户团队。
- 记住：FDE 是"**带着双向使命的工程师**"——一头向客户交付结果，一头向公司输送情报。

### 1.5 一切用结果说话（FDE 的核心信条）

"结果导向"不是口号，而是焊在角色定义里的三道机关：

- **收钱方式向结果靠拢**：Palantir 早年大量"做成了才付钱"；Sierra 按"已解决的会话"收费，不解决不收钱。收费一旦与结果绑定，团队的全部行为自动重新排序。
- **成功度量前置到开工之前**：项目第一步不是写代码，是和客户一起定义"什么叫成"。比如"把某条产线的排产冲突降 30%"，而不是"探索人工智能赋能制造"。
- **最终裁判是客户组织的行为改变**：系统上线不是里程碑，**客户团队改变工作方式才是**。反例：约九成员工绕过官方系统、私下用个人版人工智能工具干活——官方系统空转的"假成功"。

### 1.6 FDE 在团队里的四张面孔

1. **对客户**：嵌入式产品经理 + 全栈工程师（Palantir 制度化为双人组："回声"部署战略师负责诊断，"三角洲"前置部署工程师负责建造）。
2. **对公司产品线**：前哨与情报官——三个客户撞上同一个集成缺口，那不是三桩麻烦，是一条产品情报。
3. **对销售**：信任的放大器——在客户自己的数据上当场做出能跑的东西，胜过一百页幻灯片。
4. **对组织本身**：人才熔炉——FDE 的日常几乎就是创始人训练的完整预演（资源受限、需求模糊、端到端做出有价值的东西）。

### 1.7 如何招聘 FDE（给管理者）

- **画像**：招"好奇的推土机"，不招"精致的工匠"。危险信号反而包括两类传统工程文化里的宠儿：把代码优雅置于客户结果之上的工匠，和把客户每句话当圣旨的忠诚执行者。
- **面试**：用"拆解轮"代替八股——给候选人一个模糊庞大的真实企业问题（如"某银行合规团队每天人工核对三万条交易告警，九成是误报，你怎么办"），60 分钟不写代码，只看怎么追问、怎么界定范围、怎么在混乱里建立秩序。
- **定价**：接受"工程师薪酬 + 经营弹性"混合结构；奖金与客户扩展等经营指标挂钩，但**别让 FDE 背硬性销售指标**——那会把行为引向签单而不是结果。

### 1.8 如何成为 FDE（给个人）

先自测代价：出差 25%–50% 是常态；工作节奏被客户的紧急程度定义；职业倦怠风险真实存在。一句最锐利的择业标准：

> "有人把它当品牌跳板，有人说它是挂着酷头衔的咨询，两种说法都对——区别在于，你所在的公司是把现场学习回流到产品，还是把你当人天在卖。"

补课方向：**补的不是技术，是"翻译层"**——把业务问题翻译成技术问题、把技术方案翻译成高管能懂的价值语言、把现场经验翻译成组织可复用的知识。

选公司时问三个尽调问题：

1. "你们的产品平台是什么？"——没有平台底座的 FDE 是纯人力外包。
2. "现场学习怎么回流产品？"——请对方讲一个最近从现场沉淀为产品功能的实例。
3. "FDE 向谁汇报？"——向产品/工程线汇报说明模式被认真对待；向销售线汇报要小心沦为售前人力池。

### 1.9 FDE 的五层工具箱

从脚下到身后的五层能力（工具会过时，能力分层不会）：

1. **平台底座层**（公司的武器）：带着平台去现场，否则退化为定制开发。
2. **人工智能工程层**（个人的手艺）：提示词工程、检索增强（让模型先查资料再回答）、**评估体系**（为模糊的业务质量建立可量化标尺——人工智能时代 FDE 的标志性技能）、智能体架构、成本优化。
3. **数据与集成层**（进场的第一仗）：数据管道、系统连接器、权限认证。从业者经验：**项目进度的七成卡在这里，但演示里看不见它——它是冰山的水下部分**。
4. **交付与协作层**（客户环境里的生存装备）："双重适配"——既会用自己的现代工具链，也能屈身于客户可能物理断网的内网环境。
5. **知识沉淀层**（规模化的杠杆）：打法手册、组件库、部署检查清单——决定团队能否摆脱"收入随人头线性增长"。

### 本章小结

- FDE = 驻扎客户现场、填补"产品能做的"与"客户要的"之间鸿沟的工程师；它不是售前、不是外包、不是咨询。
- 这个岗位诞生于 Palantir（2003），爆发于生成式人工智能时代（2025），因为**模型不稀缺了，能把模型塞进客户真实业务的人稀缺**。
- 核心信条是"一切用结果说话"：收钱方式绑定结果、成功标准开工前定义、最终裁判是客户行为改变。
- 能力模型 = 技术通才 + 业务翻译 + 主人翁意识；工具箱分五层，平台底座和知识沉淀决定模式成败。

## 第 2 章 解决正确的问题

> 「在错误的问题上，一切执行力都是浪费。」

### 2.1 概念验证坟墓的解剖报告

- "概念验证炼狱"（POC purgatory，指验证项目既没死透也不敢加大投入、无限期"持续推进中"的状态）是行业常态。
- 企业人工智能项目的五大路障（按出现频率）：**员工不愿用新工具 → 担忧输出质量 → 糟糕的用户体验 → 缺乏高管支持 → 变革管理困难**。
- 注意清单里**缺席**的东西：模型不够聪明、算力不够贵、技术不够先进——都不在列。**杀死项目的原因几乎全部在"问题定义"和"组织现实"层面，不在技术层面。**
- 经典反面细节：企业花五万美元买的合同分析工具，资深律师就是不用——她继续用免费的 ChatGPT 起草合同，因为买的工具摘要太死板。官方系统空转、员工绕道而行。
- 扎心对比：**与外部供应商合作的项目成功率约为内部自建的两倍**——不是外部更聪明，是"按结果收钱的人，定义错问题的代价是自己买单"。
- 反面教材模板：抽调最强工程师组攻坚队、演示惊艳、领导点头，唯独从第一天起没人能回答"这套系统的好，由什么标准衡量"——半年后项目从汇报材料里悄悄消失。

### 2.2 PSF：问题与方案的契合

先解释两个术语：

- **PMF（Product-Market Fit，产品与市场契合）**：互联网创业概念，问"我的产品有没有市场要"，视角在供给方（我）。
- **PSF（Problem-Solution Fit，问题与方案契合）**：本书提出的 FDE 对应概念，问"客户这个具体的问题，值不值得、能不能被我们的能力解决"，视角在需求方（客户）。

一个企业客户内部可能有几百个"人工智能能做点什么"的机会点，真正值得做的必须过三关：

1. **痛点检验**：是不是某个具体的人的具体的痛？注意两个"具体"。
   - ❌ "提升客服效率"——这是方向，不是痛点；
   - ✅ "客服主管每周一早上要花三小时，从四个系统里手动汇总上周的升级工单"——这才是痛点。
   - 更锋利的标准：**去解决首席执行官最关注的五个问题之一**——只有这个量级的问题才能帮你碾过企业内部的官僚阻力。
2. **经济性检验**：解决这个问题值多少钱？算账公式很简单：每周消耗多少人时 × 人力成本 + 出错一次的代价 + 释放的产能能去哪。
   - 行业级教训：超过半数人工智能预算投向前台销售营销（演示效果好的场景），而投资回报实际集中在后台合同审查、采购、风控这些"不性感"的地方。
3. **可行性检验**：以我们现在的能力和客户的数据现实，能做到几分？两个必答问题：
   - 数据在哪、什么状态？（答案经常是：分散在七个系统、三个版本对不上、最权威那份在某个老员工的私人表格里）
   - 这个问题需要的准确率门槛是多少？（"99% 可用"和"90% 可用"之间隔着数量级的工程投入，很多场景 90% + 人工复核就是最优解）

**三关都必须在客户现场过——坐在总部会议室里对着二手信息做判断，是本章一切错误的总根源。**

### 2.3 拒绝昂贵的"概念验证坟墓"

- 反直觉真理：**拒绝错误的项目，是 FDE 模式最重要的盈利能力**。
- 为什么？FDE 的成本结构是前置的：最贵的工程师、差旅、现场投入全发生在回款之前。陷进泥潭不是亏一单，是整支精英团队被拖住。
- Palantir 烧得起免费试点，是因为它把试点当**风险投资组合**（多数下注归零没关系，成的赢回一切）；如果你没有它的资本厚度，也没有"失败试点转化为产品资产"的机制，每个错误试点都是纯失血。

三条可操作的防线（可以直接抄用）：

1. **防线一：概念验证必须有"毕业标准"**。启动时白纸黑字写明：多少周后、用什么指标、达到什么数值就"毕业"进入付费部署；达不到，双方体面散伙。传统验证沦为坟墓，恰因为它"无限期、无指标、无裁判"。
2. **防线二：警惕三类高危信号**（出现两个以上高度警惕）：
   - **没有土地的所有权**：项目没有明确的业务方负责人，只有信息部门在对接（信息部门关心合规与稳定，那从来不是做新项目的理由）；
   - **数据朝贡**：客户要你先证明能力，却拒绝提供真实数据（没有真实数据的验证注定做出自欺欺人的假阳性）；
   - **宇宙级需求**：第一次会议就要"覆盖全公司所有场景"的客户，往往还没准备好做任何一个场景。
3. **防线三：给"拒绝"留个体面的台阶**。把"现在不做"翻译成"什么时候做"："这个场景的数据基础还差三件事，建议先做另一个场景，顺手把这三件事补齐，下个季度再来。"——把拒绝包装成路线图。

### 2.4 痛点从哪来：影子工作法

- 核心结论：**痛点不会出现在会议室里，只会出现在工作现场**。士兵不知道"可以向软件要一个路边炸弹预警工具"，他们以为那就是巡逻生活的一部分——**痛点是被工程师"看见"的，不是被用户"说出来"的**。
- 方法名：**影子工作法**（源自人类学"参与式观察"和丰田"现地现物"）：跟着真实用户，过完他真实的一天。不是采访他，是坐在他旁边看他工作。
- **重点观察"变通"，而不是"流程"**：
  - 官方流程图告诉你组织"应该怎么运转"；变通告诉你组织"实际怎么运转"。
  - 每一个变通都是一个未被满足的痛点在尖叫：员工为什么把数据导出到表格再算一遍？为什么公认"这张表要找小王"？为什么决策会前总有人手动核对数字？
  - 变通是组织的疤，每道疤下面都是一次系统的失败，也都是 FDE 的机会。
- **警惕"翻译过的痛点"**：经过信息部门、采购部门转述的痛点每转一次失真一次（信息部门把业务痛点翻译成"需要一个数据平台"，采购翻译成"需要满足某某标准"）。FDE 的第一要务是**绕过翻译件，直达疼痛的神经末梢**。

### 2.5 最小可行部署（MVD）

先解释术语：

- **MVP（Minimum Viable Product，最小可行产品）**：互联网概念，用最小的产品验证市场需求，裁判是"市场"。
- **MVD（Minimum Viable Deployment，最小可行部署）**：本书提出的 FDE 对应概念——用最小的工程投入，在客户的真实环境里，对真实的痛点，验证一次价值的真实发生，裁判是"这个具体客户的具体业务"。

关键区别：MVP 验证一次可以复制推广；**MVD 的价值不能继承，只能逐个客户验证**（数据基础不同、组织惯性不同、痛点形状不同）。

MVD 三条军规：

1. **真实数据，没有例外**。用"脱敏样例数据"或自己编的演示数据做验证，是概念验证坟墓的第一块砖。在假数据上成立的方案，只是精心制作的自我安慰。
2. **缩小切口，而不是缩小野心**。常见错误是把 MVD 做成"阉割版大方案"；正确做法是换一个维度缩小——**不砍价值，砍范围**：
   - ❌ "覆盖全公司的智能客服（功能砍掉七成的版本）"；
   - ✅ "只覆盖退换货这一类工单，但做到端到端、无人干预"。
3. **时限死线，倒逼取舍**。验证周期以"周"计不以"月"计（Palantir 训练营一到五天；Sierra 最快案例四周；Decagon 典型四到八周）。凡不能在这几周里体现价值的部分，都还不是核心价值。

**训练营：MVD 的工业化流水线**（Palantir AIP Bootcamp，目前唯一被大规模验证的 MVD 流水线）：

| 天数 | 动作 |
| --- | --- |
| 第 0 天 | 筹备：锁定一个极其聚焦的核心战场（如"优化某条产线排产"），拒绝宏大叙事 |
| 第 1 天 | 接入：打通客户现有系统，抽出孤立数据，构建初步本体模型 |
| 第 2–3 天 | 构建：FDE 与客户技术人员背靠背写代码、配规则，把大模型接入业务流 |
| 第 4–5 天 | 演示与拍板：产出活的软件界面，业务高管亲手点击，之后直接进入商务谈判 |

效果数据：企业软件传统销售周期（九到十二个月）被压到数周；大型医疗公司训练营后五周签五年期、年合同额 2600 万美元的协议；Walgreens 从 10 家门店试点（效率提升 30%）到八个月推到 4000 家门店。

对没有平台底座的团队，可执行的简化版是"**两周冲刺验证**"：

1. 第一周：进场、接数据、定指标；
2. 第二周：做出一个只解决单点问题、但能跑真实业务的原型；
3. 周末：向业务方演示，当场决定进退。
4. 记住：**形式可以裁剪，军规不能裁剪**。

### 2.6 早期要不要迁就客户的现有环境

几乎每个项目都会撞上这个分歧（客户的二十年老系统、严格的安全边界），FDE 的中间路线叫"**读旧写新**"：

- **数据层面——深度兼容旧环境**：客户的数据在哪就从哪读（哪怕在老式主机、共享盘表格、古老系统的私有接口里）。数据是验证价值的前提，数据永远不会为了迁就你的架构而搬家。
- **架构层面——坚决不做旧环境的寄生体**：验证期系统应运行在自己可控的边界内，通过接口与旧系统交互，不把代码写进旧系统。三个理由：验证期方案有一半以上概率被推翻重写，寄生越深浪费越大；写入旧系统要走客户变更管理流程（周期以月计，与周级节奏冲突）；保持"可撤离"本身就是谈判筹码。
- **流程层面——顺从人的习惯，而不是系统的习惯**：如果业务用户的核心动作发生在表格和邮件里，界面就应该出现在表格插件和邮件里。**新系统最大的敌人不是旧系统，是旧习惯**。

### 2.7 "行胜于言"的用户调研

传统调研信条是"问"（问卷、访谈、焦点小组）；FDE 的信条是"看"和"做"。三层原因：

1. **客户不知道自己要什么**（认知规律，不是贬低）：面对全新品类，用户没有参照系。人对"哪里不对"的判断力，远强于对"要什么"的想象力——所以 Palantir 不问"你要什么"，而是说"这是我做的东西，你来说说哪里不对"。
2. **客户说的和做的是两回事**：问卷里"愿意使用专业工具"，实际行为是继续用 ChatGPT 干活。**只有行为不会撒谎**。
3. **最高质量的调研发生在共同劳动中**：并肩干活时客户是同事、松弛而真实；调试间隙随口说出的"其实这个字段我们从来不信"，在正式访谈里永远不会出现——而这恰恰是部署成败的关键情报。

一句话浓缩本章方法论：**用影子工作法找到痛点，用最小可行部署验证方案，用共同劳动赢得真相**。

### 本章小结

- 企业人工智能项目死于"问题定义"和"组织现实"，不死于技术。
- 选问题过三关：痛点检验（具体的人的具体的痛）、经济性检验（算得清账）、可行性检验（数据现实 + 准确率门槛）。
- 建立拒绝机制：毕业标准 + 三类高危信号（无业务负责人 / 拒给真实数据 / 宇宙级需求）+ 体面台阶。
- 痛点靠"看"不靠"问"：影子工作法 + 观察变通 + 警惕翻译过的痛点。
- 用 MVD 验证价值：真实数据、缩小切口不缩小野心、周级死线；训练营是 MVD 的工业化形态。
- 环境策略"读旧写新"：数据深度兼容、架构不寄生、习惯要顺从。

## 第 3 章 赢得客户

> 「企业买人工智能，就像你奶奶拿到一部苹果手机——她想用，但需要你帮她设置好。」——a16z

### 3.1 筛选你的灯塔客户

- **灯塔客户**：不仅能给你收入，更能给整个行业"发信号"的客户。
- 灯塔的三重战略价值：
  1. **最强的销售资产**：企业决策链长、同行背书是最短说服路径。Harvey 第一个大客户是顶级律所年利达（3500 名律师）——拿下它等于拿到整个顶级律所市场的通行证。
  2. **决定你的产品基因**：FDE 模式下前十个客户在事实上参与塑造你的产品，选错灯塔产品会被带向没有普遍性的方向。
  3. **质量比数量重要一个数量级**：一支精英团队同期能深度服务的客户是个位数；接错一个的代价是"一支顶尖团队被泥潭占用半年"。
- 灯塔特有检验：**这个客户愿不愿意在成功后站出来？**（联合发布案例、行业会议现身说法、接待潜在客户参访——这些承诺要在合作初期就摆上桌面。一个不能讲的灯塔，照明价值减半。）
- **警惕"需求蝗虫"**（预算充足、需求旺盛、但吸干团队却不产生复利的客户），三个识别特征：
  1. 需求与公司战略方向明显偏离，做了也沉淀不下可复用能力；
  2. 把 FDE 当廉价外包使唤，按人头派活而不是按结果对齐；
  3. 内部政治消耗巨大，你的主要工作变成帮某个部门证明另一个部门错了。

### 3.2 从最笨的事情做起

- YC（著名创业孵化器 Y Combinator）古训："做不可规模化的事。"麦格鲁的对应表述：**FDE 模式，就是在规模上做不可规模化的事**——在企业市场，信任的获取没有规模化捷径，只有笨办法。
- 三个层次：
  1. **人要到场**：企业客户的信任按"见面次数"和"共同经历的事"计价。远程会议建立的是熟悉，只有并肩作战建立的才是信任。
  2. **手要弄脏**：OpenAI 的 FDE 在爱荷华农田跟着农艺师下地——只有踩过农田的泥，你才理解为什么那个"完美的手机界面"在户外强光下根本没法用。
  3. **先做仆人，再做导师**：进场初期别摆"我们来拯救你们"的姿态（姿态一错，一切情报通道关闭）。先帮分析师修一个数据问题、帮信息部门补一份接口文档。这些笨事换来三样战略资产：组织内部的真实地图、数据环境的真相、"这个外来者是自己人"的身份认证。

### 3.3 信任红利：标杆客户的背书矿藏

- 企业市场的信息信任排序（从低到高）：厂商宣传 < 分析师报告 < 同行公开案例 < **同行私下推荐**。FDE 交付的不是软件许可证，是客户高管在同行饭局上的一句"他们真的懂行"。
- 开采背书矿藏的三层动作：
  1. **把交付做成"可讲述的故事"**——三个叙事要素缺一不可：一个具体的数字（"化学品使用减少 70%"）、一个具体的人（"我们的农艺师和他们团队一起在地里干"）、一个具体的反差（"以前三个月，这次五天"）。主动帮客户内部支持者备好一页纸、三张图、一个 30 秒能讲完的版本。
  2. **把客户的成功变成客户的社交货币**——最理想状态：客户把你的方法论当作它自己的行业领导力来展示（J.D. Power 参加完 Palantir 训练营后，开始为自己的客户办训练营）。
  3. **小心背书的反噬**——企业市场是记仇的：一次高曝光失败传播速度远快于十次成功，**灯塔战略的死穴不是找不到灯塔，是让灯塔在你手里熄灭**。

### 3.4 用数据摸清客户家底：进场尽调的五份地图

进场尽调（写第一行代码之前，用一到两周结构化摸清客户全部家底）要画五张地图：

1. **数据地图**：有哪些数据源、谁拥有、质量如何、权限归谁。重点不是"有什么"，是"**哪个被信任**"——几乎每个组织里，官方数据源和员工真正信任的数据源都不是同一个，后者才是你要接的。
2. **流程地图**：目标业务流程的**真实**运转图（影子工作法观察出来的版本，不是流程文件里的版本）。特别标注三个点位：时间消耗最大的环节、出错代价最大的环节、情绪最激烈的环节——这三个点位通常是价值的富矿。
3. **组织地图**：谁发起、谁买单、谁使用、谁能否决、谁是无冕之王。特别要找"**知识枢纽**"：职位不高但所有人遇到实际问题都去找他的人——他们既是最好的需求来源，也是日后推广的种子节点。
4. **系统地图**：要对接的系统清单及接口状态、安全合规边界、变更管理流程。很多项目的时间表在第一天就注定破产，因为没人问清楚：客户那边发布一个版本要走六周流程。
5. **政治地图**（最敏感也最关键）：这个项目动了谁的奶酪？抵触的根源大多不是懒，是**恐惧**——怕被取代、怕被证明无能。政治地图的功能是提前识别这些恐惧的载体，并在方案里给他们安排"新生路"而不是"死路"。

账要这么算：**两周尽调省下的，是三个月在错误战场上的狂奔**。

### 3.5 技术内容营销：信任的预售

- FDE 公司的内容营销独特定位：**不追求流量，追求"专业信任的预售"**——客户遇到难题、搜索打听时发现"这家公司对这个问题有过极其专业的公开论述"，得出结论"他们懂，找他们"。
- 三条军规：
  1. **写"战壕视角"，不写"展台视角"**：常规企业内容讲产品多强；FDE 内容讲问题多难、怎么趟过去的。Barry 那篇"自曝家丑"（讲重复造轮子的浪费、负利润率试点、被烧干的工程师）的文章反而成了 Palantir 模式最好的布道。
  2. **方法论开源，制造"被引用的资格"**：把自己的方法论公开，短期是教会同行，长期是定义行业标准——当客户都用你的框架提问时，你就从供应商变成了出题人。
  3. **让客户的内部支持者成为内容里的英雄**：案例文章主角应该是客户方那个有远见的管理者，你的团队是"帮助他成功的伙伴"。

### 3.6 采购、法务与安全审查的通关术

关键认知转换：**这三道闸门不是交付的阻碍，而是交付的一部分**。把它当阻碍会在最后一公里翻车；把它当交付内容会在竞争里建立优势。

- **采购关**：采购部门的职责是控价控险合规，压价不是针对你。应对之策是给他们"可交差"的工具：清晰的分阶段报价（让降价有台阶）、可对比的市场基准（让审批有依据）、可衡量的结果承诺（让"买贵了"的指控无从成立）。
- **法务关**：把数据处理协议当产品来打磨——预置协议模板、清晰的模型使用声明、分级的事故责任框架。**法务信任是设计出来的，不是谈判出来的**。
- **安全审查关**：主动维护一份"安全白皮书"（部署架构图、数据流图、加密与权限方案、历史被问问题的标准答案），多数问卷八成可以直接复制粘贴。你的响应速度本身就是安全成熟度最直观的信号。

### 3.7 生态捆绑：站在渠道的肩膀上

借三类伙伴的肩膀：

1. **云厂商与大平台**：进入联合销售体系等于获得直达企业采购清单的通行证；客户还能动用既有云预算采购，绕开新增供应商流程。
2. **咨询公司与系统集成商**：模型公司有技术、咨询公司有客户关系、集成商有落地人力——三方合流（OpenAI 部署公司的创始伙伴包括麦肯锡、贝恩、凯捷）。中国同款剧本：火山引擎 × 安永共建千人级 FDE 团队。
3. **客户的客户**：最高级的捆绑是嵌进客户自己的价值链（J.D. Power 用 Palantir 的方法服务自己的客户）——这时你就从供应商变成了客户商业模式的一部分，那是最深的护城河。

### 3.8 排期：谁先谁后，本身就是战略

- 残酷现实：一支合格的前置部署小分队（一业务侧 + 二三技术侧）同期能高质量交付的项目**不超过两个**。
- 三条排期原则：
  1. **按战略价值排，不按合同金额排**：决策矩阵只有两个维度——灯塔价值（行业信号强度）× 学习价值（能沉淀多少可复用能力）。两维都高的客户可以倒贴资源优先做；两维都低的大合同反而是产能陷阱。
  2. **把"等待"产品化**：给排队期设计预备动作（数据准备清单、组织预热建议、轻量远程诊断）——等待期经营得好，进场后交付周期能缩短三分之一。
  3. **永不承诺超越产能的并行**：多项目切换的损耗远大于常规认知（每个项目背一整套客户语境，切换一次重新加载一次）。可以把"档期排到下季度"当稀缺性信号卖（往往还能提价）。

### 3.9 用开源工具与体验装让品牌无所不在

- 逻辑：企业采购的发起者是高管，但**技术否决权在工程师手里**——让目标客户的工程师先用上你的东西，等于在决策链技术端预埋信任票。
- 三种载体：开源交付中沉淀的通用模块（评估框架、连接器、部署模板）；可自助体验的技术橱窗（演示环境、沙盒、快速上手包）；工程师在目标行业技术社区的存在感。

### 3.10 提案与验证方案的撰写

坏提案的通病：通篇讲"我们要做什么"，而不是"你将得到什么"。好的 FDE 提案遵循严格的**倒金字塔结构**：

1. **第一层：业务结果，一段话说完**（客户语言）："八周内，把你行反洗钱调查的平均处理时间从 4 小时降到 15 分钟。"没有这一句，后面所有技术内容都没有阅读语境。
2. **第二层：价值验证路径**：验收指标、测量方法、基线数据、每阶段的退出机制——传递"我们敢被检验"的信号。
3. **第三层：交付方法**：架构图配业务注释、里程碑配决策点；**显性写明需要客户配合的事项**（数据访问、关键人员时间）——既是排雷也是筛选。
4. **第四层：风险与对策**："我们想过会怎么死"：数据质量不达标怎么办、关键人员变动怎么办。把死法说清楚的供应商，反而最被成熟买家信任。

### 3.11 从驻场到远程：混合交付的边界

- 进化方向：从纯驻场走向"远程为主 + 关键节点驻场"。
- **必须物理在场**的三类时刻：关系建立初期（信任的肉身性无可替代）、高强度共创（训练营式联合构建）、政治敏感期（需要读懂会议室里的空气）。
- **远程反而更好**的事：深度编码、文档沉淀、常规迭代。
- 隐性红利：驻场是 FDE 成本里最大的可变项，合理混合比例能把交付利润率拉出十个点以上；也降低团队倦怠率。
- 底线：**"从不见面"的 FDE 是伪命题**——远程只能维持已有的信任与语境，而它们必须先在物理世界里被创造出来。

### 3.12 海外扩张（要点）

- 美国巨头的 FDE 地理分布精确描摹出企业人工智能付费能力的全球地图：北美、西欧、东亚发达经济体、中东主权财富。
- 中国视角的反向洞察：**中国的交付工程师文化（能吃苦、响应快、全栈通吃、习惯在客户现场解决一切）恰恰最接近 FDE 要求的工程文化**——问题不在人合不合适，在平台底座够不够厚。
- 出海节奏必须克制：先用远程可交付的产品层建立滩头，再在重点市场落本地交付团队，一口一口吃。

### 本章小结

- 赢得客户 = 选对灯塔（能发信号、愿站出来）+ 笨办法建立信任（人到、手脏、先做仆人）。
- 进场先画五张地图：数据、流程、组织、系统、政治——重点找"被信任的数据""知识枢纽""受损者"。
- 把采购/法务/安全审查当交付内容而非阻碍：可交差的工具、产品化的协议、预答白皮书。
- 排期按战略价值不按金额；把等待产品化；永不超载并行。
- 提案用倒金字塔：业务结果 → 验证路径 → 交付方法 → 风险对策。
- 一句话总结本章：**在一个被辜负过无数次的市场里，成为值得被信任的那个例外**。

## 第 4 章 激活部署

> 「模型通常是最干净的部分。难的是找到那个没人写进文档的工作流程。」——一位一线 FDE

### 4.1 上线不等于激活：首日魔咒

- **激活的定义**（本章核心概念）：目标用户群体在日常工作中，形成对系统的稳定使用习惯——不是演示会上鼓掌，是三个月后没人催、系统依然被高频使用。
- **"上线"是行政事件，"激活"才是行为事件。前者可以庆祝，后者才算数。**
- 企业系统激活失败的三大死因（与消费产品死于"不好玩"完全不同）：
  1. **不顺手**——比旧习惯多一步，就没人用；
  2. **不可信**——错一次，信任清零；
  3. **不动人**——没有人觉得这事与自己有关。
- 这三件事没有一件能在总部解决，全部发生在客户的会议室、车间和工位上。**激活是 FDE 模式的主场，也是 FDE 与"交付即走"的传统实施最根本的分野：传统实施的终点是验收单，FDE 的里程碑是客户行为改变。**

### 4.2 快速迭代：部署期的"热修复"文化

- FDE 部署期的迭代节奏以"天"甚至"小时"计：上午用户说"这个输出少了供应商编码字段"，下午字段就加上。**每一次隔夜的修复，都是对用户信任的一次充值**——用户在第一个月就会形成判断："这个团队是来真的"还是"又一个交完就走的"。
- 三个执行要点：
  1. **反馈通道必须短到没有中间层**：用户反馈直达写代码的人，最好写代码的人就坐在用户旁边。传统链路（用户→客户成功→产品经理→排期→工程师）每层转述丢一半上下文。
  2. **迭代优先级按"使用阻塞度"排序，不按"功能重要度"排序**：一个配色问题如果让车间工人觉得"这是给办公室白领做的"，它就是最高优先级；一个强大的预测功能用户当前用不上，就排到激活完成之后。**先赢使用，再赢深度。**
  3. **每天收工问一个问题**：今天的改动，让用户明天的哪一刻更顺了？——把热修复从"响应姿态"升级为"激活工程"。

### 4.3 评估体系驱动的质量爬坡

先解释术语：**评估体系**（Evaluation）= 用一批标准案例，给人工智能系统的输出持续打分的机制。可以理解为"给人工智能准备的考试题库 + 评分标准"。

为什么必须有它：

- 传统软件质量是二值的（功能对/错）；人工智能质量是连续的、概率的、场景相关的——同一个回答在演示里惊艳，在具体业务语境里可能是灾难。
- **"好"的定义权在业务方不在工程方**：模型觉得完美的回答，业务专家可能一眼看出外行。没有评估标尺，迭代就是蒙眼狂奔。

三步搭建（可直接照做）：

1. **从真实案例里长出来**：评估集不能靠工程师编，必须来自客户的真实业务语料——本质是把业务专家的隐性判断力，显性化为可执行的标尺。
2. **让业务方成为评委**：做成业务专家能参与的形态（并排的输出对比、简单的优劣标注、定期评审会）。双重收益：评估集越来越准；业务方看着系统在自家案例上一次比一次好，**信任的积累是亲眼所见，而非汇报所得**。
3. **接到生产回路上**：生产环境持续采集真实输入输出，定期抽样评估，分数下滑立即告警。**用户最敏感的不是平均质量，是质量的稳定性：错一次造成的信任塌方，需要十次正确才能填回来。**

标杆案例（约翰迪尔）：OpenAI 的 FDE 飞到爱荷华，跟着农艺师下地，**先和专家一起评审数百个真实作业案例、建起定制评估体系，然后才开始迭代模型**。最终"化学品使用减少最高 70%"这个数字不是事后包装的宣传口径，是开工前就定好的靶子。**先有评估体系定义的"好"，才有模型交出的"好"。**

### 4.4 降低使用门槛的四种手法

1. **寄生在用户已有的界面里**：用户在表格里工作就做表格插件，在邮件里审批就让审批在邮件里完成。**每多一次登录，激活率就流失一截。**
   - 标杆案例（西班牙对外银行 BBVA）：从 12 万员工已经在用的 ChatGPT 界面切入，不另起炉灶。路径：3300 个账号起步 → 员工自发创建 2 万多个定制小助手 → 83% 周活跃、人均每周省约 3 小时 → 扩展到 25 国 12 万人。每一步扩张都发生在上一步的使用数据被公布之后——**让习惯自己走路**。
2. **默认值里藏着激活率**：新用户面对空白系统的第一反应是"然后呢"，多数流失发生在这三秒。把"第一次使用"预装好：预置模板、预填示例（基于客户自己的数据）、预设引导。
3. **把"问人工智能"翻译成"点按钮"**：把高频场景封装成一键动作（"生成上周异常报告""核对这批发票"），按钮背后是经过评估调优的完整流程。**对话式交互留给探索，按钮式交互留给日常。**
4. **先做"副驾驶"，再谈"自动驾驶"**：高风险流程让系统先以"建议者"身份存在（人工智能起草、人来确认），等确认通过率高到某个水位再上自动化。副驾驶策略不是保守，是激活率与风险之间的最优路径。

### 4.5 旷日持久的集成大战

- 集成（把你的系统和客户的老系统连通）是 FDE 老兵共同的伤疤来源：上下文全部锁在企业内部的数据库、接口和工作流里，而文档过时、接口残缺、懂它们的人退休了一半。
- 四个战略要点：
  1. **把集成当战役打，不当杂务办**：多数项目计划里写"系统对接：2 周"，执行中膨胀为四个月。正确姿势：进场尽调就画出系统地图，集成风险分级排期，**最硬的骨头最早啃**。
  2. **数据问题先于模型问题解决**："垃圾进垃圾出"——人工智能接了未治理的数据，同一个文档十个版本随机命中，输出自然不可信。**数据治理不是人工智能项目的前置工程，它就是人工智能项目本身。**
     - 壮观注脚（美国海军）：先花大力气把造船厂数据接进统一语义层，然后**潜艇排产计划从 160 个人工小时压缩到 10 分钟以内**、物料审核从几周到一小时。
  3. **用人工智能打人工智能的集成战争**：没有接口的老系统用浏览器智能体模拟人去取数；字段映射、格式转换大量交给模型处理。
  4. **知道什么时候绕开，而不是攻克**：有些系统的正确解法是"影子读取"（只读快照、夜间同步）、"人工摆渡"（过渡期保留人工环节）或干脆"宣告隔离"。**你的目标不是技术全胜，是客户结果。**

### 4.6 变革管理：让客户组织为你站台

激活最大的软阻力是组织。变革管理核心是经营三组人物：

1. **支持者**（你的内部盟友）：经营要点——给他弹药（可讲述的叙事）、给他战功（把他的远见变成他职业生涯的亮点）、给他安全感（失败时你顶在前面）。**一个被善待的支持者，胜过十场产品宣讲会。**
2. **影响者**（非正式意见领袖：资深分析师、车间老师傅、"问他就行"的人）：他们的一句"这玩意儿还真行"抵过管理层三封全员邮件。经营手法：请他们第一批试用、认真对待每条吐槽、**把采纳他们的建议显性化**（"这个字段是按王师傅的意见加的"）。让影响者成为共同作者，是破解"不是我做的东西我不用"心态的最短路径。
3. **受损者**（方案触动的利益群体：被压缩存在感的审批岗、被穿透信息壁垒的部门）：忽视他们，他们会成为最顽强的地下抵抗者。成熟做法是提前设计"受损者的出路"：把被释放的人力导向更高价值的工作并公开承诺不裁员；把"守门人"转型为"教练"（老师傅的经验用来训练系统）。**这既是人道，也是纯粹的功利——抵抗的成本远高于安抚的成本。**

变革管理的终极检验标准只有一个：**当你的团队撤场后，系统是否依然被使用。如果你在场时热火朝天、撤场后迅速冷却，那不是激活，是伴舞。**

### 4.7 交付工作本身的自动化

- 给客户交付自动化是产品；让自己的交付工作自动化是效率——这是 FDE 团队摆脱"收入随人头线性增长"的第一杠杆。
- 执行原则：**每一个第二次做的动作，都应该触发一个提问："这能变成脚本、模板或清单吗？"**
- 四类资产：
  1. **部署模板**：环境搭建、权限配置、监控接入打包成一键式基础设施代码——新客户第一天就能拉起标准化环境（Decagon 把简单场景部署压到 15 天的底气）。
  2. **集成组件库**：主流系统的连接器，写一次处处复用。
  3. **检查清单文化**：安全审查清单、上线准入清单、撤场交接清单——**把"依赖个人经验"变成"依赖组织记忆"**。
  4. **自动化汇报**：周报、现场情报半自动生成——FDE 的时间单价太高，不该花在复制粘贴上。
- 回应"FDE 不就是人海战术吗"：人海的本质不是人多，是每个人都在做不可复用的一次性劳动。**当一支 FDE 团队的每一次交付都在为下一次交付修路，它就不再是人海，而是一台正在自我加速的机器。**

### 本章小结

- 上线 ≠ 激活：激活 = 目标用户形成稳定使用习惯，是行为事件不是行政事件。
- 激活三死因：不顺手、不可信、不动人——全部只能在客户现场解决。
- 七件武器：热修复文化（反馈零中间层、按使用阻塞度排序）、评估体系（真实案例长出来、业务方当评委、接生产回路）、降门槛（寄生旧界面、预装默认值、封装按钮、先副驾驶）、集成战争（当战役打、数据先行、用人工智能打集成、会绕开）、变革管理（经营支持者/影响者/受损者）、交付自动化（模板/组件/清单/自动汇报）。
- 检验标准：撤场后系统依然被使用。

## 第 5 章 守住续约

> 「如果你在场时热火朝天、撤场后迅速冷却，那不是激活，是伴舞。」

### 5.1 续约与流失：先算账

- 账本事实：企业级生意的获客成本（数月销售周期 + 训练营投入 + 验证成本）动辄数十万美元，而续约的成本趋近于零。**续约率就是 FDE 商业模式的生死线。**
- 企业客户流失不是静悄悄的卸载，是一场漫长的凌迟：使用率阴跌 → 例会上被质疑"值不值" → 续约谈判被"明年再看"推迟 → 某个预算季被连根拔掉。
- 五类流失死因（按可预防性排序）：
  1. **价值蒸发**：系统还在跑，但没人记得它解决了什么问题——当初的业务问题被解决后，没有人向组织（尤其新上任的管理者）持续重述"我们为什么有这套系统"。**价值不是一次性证明的，是需要不断重新证明的。**
  2. **支持者离场**：内部盟友升职调岗离职，继任者没亲历过当初的选择，把系统当"前任的政绩工程"。行业黑话："支持者一动，合同就悬。"
  3. **质量漂移**：业务在变、数据在变、模型在更新，输出质量缓慢下滑，信任随之缓慢塌方——等管理层注意到时通常已经晚了。
  4. **成本反噬**：用量越大账单越高，价值叙事跟不上账单增长时，"成功"反而成了续约障碍。
  5. **供应商戒断反应**：客户对"被绑定"的警惕。高德纳预测到 2028 年 70% 的企业将因供应商成本过高与内部技能不足而放弃前置部署主导的方案——**如果你的模式让客户感到被绑架，市场会集体反抗**。
- 核心度量指标：**净收入留存（NRR）**——衡量同一批老客户今年比去年多付还是少付了钱。超过 100% 意味着不签任何新单、存量生意也在增长。顶级水平：Palantir 2025 年第四季度 NRR 139%。

### 5.2 优化系统性能与稳定性

- 企业用户对"慢"的容忍度其实高于消费者，但对"不可靠"的容忍度趋近于零。可靠性权重是消费场景的十倍，原因：输出进入真实业务决策（一次错误的库存建议可能抹掉系统一年的收益）；错误会被放大传播（错一次传三个月，对一百次无人记得）；信任建立以季度计、摧毁以分钟计。
- 四道工事：
  1. **服务承诺可见**：可用性、延迟、错误率承诺做成客户自己也能看的监控面板——把"系统很稳"从你需要辩白的立场，变成客户随时可查的事实。
  2. **为人工智能的"概率性"设计护栏**：低置信度输出必须标注或转人工；高风险动作必须人在回路（关键动作保留人工确认环节）；模型重大更新必须过评估回归。金融、医疗场景里，**可审计性（每个决策可回放证据链）不是加分项，是准入证**。
  3. **值班与响应的仪式感**：凌晨两点系统挂了的反应速度，就是客户对这段关系的体感温度。企业客户能接受事故，不能接受隐瞒。
  4. **容量与成本同步规划**：永远跑在用量曲线前面半步——**最好的性能工作，是无人察觉的工作**。

### 5.3 有损服务：放下不必要的坚持

先解释术语：**有损服务**（源自互联网产品设计）= 在极端场景下主动降低非核心功能的质量，保住核心价值。

FDE 语境下它关乎"定制化与标准化之间的撕扯"。放任客户需求定制不停，三个月后部署里长满只有三个人在用的定制功能，维护成本全由你背——这叫"定制债务"，同时腐蚀利润和敏捷。

在三个维度主动做减法：

1. **功能维：敢对长尾需求说"不做"**。判断标准不是需求是否合理（多数需求单独看都合理），而是两个问题：它服务的用户数 × 频率，值不值终身维护成本？它能否泛化为平台能力？两个都答否的需求，最好的回应是**提供变通方案，而不是代码**。
2. **承诺维：分级承诺，而不是一律最高**。核心交易链路按最高标准守护，报表与探索性功能坦然接受"有损"（高峰期关闭重计算、重任务夜里跑、分级承诺事先言明）。
3. **成本维：用量账单的主动管理**。给出成本优化方案（缓存、批处理、模型分层——用便宜模型处理简单请求）；重新设计计价结构；**在客户财务负责人问起之前，先把"这笔账单对应的价值账"算给对方看。等你被叫去解释账单时，你已经输了一半；主动把账算清的人，续约谈判时手里全是牌。**

### 5.4 引导新用户快速上手

- 企业系统的"新用户引导"是永不结束的滚动过程（新员工入职、组织调整、新部门纳入）——设计得好使用率随时间爬坡，设计得差使用率随最初那批被培训的用户流失而衰减。
- 与消费产品的根本不同：消费产品引导是一次性自助流程；**企业系统引导是"人传人"的组织工程**。
- 三个可复用结构：
  1. **分层培训**：管理员/内部支持者深度培训（未来角色是内部专家）；普通用户场景化培训（只讲"你的日常三件事怎么用系统做"，30 分钟封顶）；高管一句话培训（"打开这里，这个数字就是答案"）。
  2. **"培训培训师"杠杆**：识别客户组织里的热情分子，培养成内部讲师——给予官方认证、专属支持通道、高管面前的曝光机会。**教会客户教自己，是交付的最高形态。**（规模样本：埃森哲培训三万名顾问使用 Claude，再把这支队伍带进自己的客户。厂商培训的从来不是"用户"，而是"会去培训别人的人"。）
  3. **文档与自助体系**：企业文档的宿命是写完无人读，除非符合两个标准——以任务而非功能组织（"如何处理一笔异常退款"而非"退款模块功能说明"）、嵌入产品而非独立存在（在用户卡住的地方就地出现）。

### 5.5 组织维系与单点依赖

- 单点依赖的形成几乎自然：项目由支持者发起、关系靠支持者维系、成功叙事由支持者代言——然后某天他离开了，你的系统在继任者待办清单上排不进前二十。
- 三处防御工事：
  1. **关系的网格化**：一个支持者之外，至少再发展两条独立关系线（业务线的日常使用者社群 + 更高一层的高管赞助人）。检验标准：**任何单个人离开，信息通道都不中断**。
  2. **价值的组织化**：把系统价值从"支持者的政绩"改写为"组织的资产"——价值数据定期全员通报、成功案例在内部会议反复讲述、**把系统嵌入流程文件**（当系统被写进标准作业流程，替换它就需要改写流程——最强的制度性锁定）。
  3. **离场的仪式化**：支持者离开时，办一场得体的"功成"仪式（感谢信、成就总结、赠予可带走的职业资本），同时以"帮助继任者快速出成绩"为切入启动交接。**善待离场者，是把流失风险转化为获客通道**（他去了新东家，就是你下一个客户的潜在入口）。

### 5.6 设计健康度与唤醒机制

把守护续约的全部动作收拢为一个系统——**客户健康度体系**，目标是让"关系变质"从突然死亡变成一条早就被监测到的缓慢曲线。

- **四类信号合成健康分**：
  1. 使用信号：周活跃用户趋势、关键功能渗透率、使用深度（是不是打卡式使用）；
  2. 价值信号：当初定的业务指标现在如何、投资回报故事是否依然成立；
  3. 关系信号：支持者在职状态、最近 30 天高层接触次数；
  4. 商业信号：用量与账单比率趋势、合同到期时间、竞品动向。
  - 精髓不在分数本身，在于**迫使团队每周用数据的眼光巡视一遍全部客户**。
- **季度业务回顾（QBR）**三个纪律：讲客户的语言不讲产品语言（"为你们节省了多少工时"而非"我们上线了什么功能"）；让客户的业务方当主角；以"下一季度的价值计划"收尾——**续约不该是到期前的一次谈判，而是每个季度都在自然续写的连续剧**。
- **唤醒机制的分级响应**：轻度下滑（某部门使用减少）→ 内部讲师上门回访；中度下滑（整体活跃降三成）→ FDE 团队专项诊断（通常是业务变化、人员变动或质量漂移三者之一）；重度下滑（濒临停用）→ 高管层坦诚对话，有时答案是体面的退出或降级——**保住关系与口碑，为未来的重逢留门**。

### 本章小结

- 续约是生死线：获客成本数十万美元，续约成本趋近于零。
- 五类流失死因各有解法：价值蒸发 → 持续重述价值；支持者离场 → 关系网格化 + 价值组织化 + 离场仪式化；质量漂移 → 评估体系接生产回路 + 护栏；成本反噬 → 主动算账；戒断反应 → 知识转移、做完会走。
- 有损服务的智慧：功能上敢拒绝长尾需求、承诺上分级、成本上主动管理。
- 健康度体系 = 四类信号（使用/价值/关系/商业）+ 周巡视 + 分级唤醒；季度回顾把续约变成连续剧。

## 第 6 章 扩大收入

> 「FDE 模式成立的标志是：每个后续客户的定制量递减。」——鲍勃·麦格鲁

### 6.1 免费验证的世界

- 企业人工智能时代最昂贵的免费，是免费的概念验证——但三本账算得过来：
  1. **获客成本的重定价**：免费的验证不是成本，是**把销售费用换成了工程师费用——而工程师费用能沉淀为产品，销售费用不能**。
  2. **风险定价的权力**：主动承担风险（"做成了你再付"）溶解客户对新供应商的疑虑；当怀疑被溶解，客户买的不再是"一个赌"而是"一份已被亲眼验证的确定性"——**确定性是可以溢价的**。
  3. **失败也要让失败值钱**：传统销售失败留下一堆差旅发票；FDE 式免费验证失败留下对行业的理解、可复用组件、评估数据——前提是建立了回流机制。
- 致命前提：免费必须是"毕业制"的，不能是"无限居留制"的。

### 6.2 免费午餐的终结：验证转付费的五个开关

1. **毕业标准先于开工**：周期上限、验收指标、达标后进入商务谈判的约定，白纸黑字。Palantir 训练营把"拍板"直接写进第 4–5 天的日程表——**转化不是事后事件，是日程表上的一个格子**。
2. **免费的边界显性化**：客户必须清楚免费到哪一天、覆盖什么范围。模糊的免费边界会培养"免费是常态"的预期，收费日客户感觉不是"开始付费"而是"被宰了一刀"。
3. **让内部支持者成为销售员**：真正敲预算门的是客户内部亲眼见证价值的支持者。你的工作是武装他：一页纸价值报告（数字、对比、同事证言）、应对财务质询的问答集、"如果不继续"的机会成本陈述。
4. **价格锚点的提前埋设**：免费期就开始谈价值（"这套系统这个月为你们释放了约 120 个人时"）——报价单出现时客户心里已有锚点。
5. **给"不转正"设计体面的出口**：保留数据与配置、约定重启条件、维持轻量联系。企业市场很小，今天的"明年再说"常常是后年的大单。
- 一句话：**把"免费到付费"从一次惊险的跳跃，设计成一段缓坡**。

### 6.3 成果计价：寻找价值的"热追踪弹"

先解释背景：在线软件时代主流按账号数收费（为"使用权"付费）；但当一个智能体能完成 10 个人的工作，按账号收费就成了笑话。于是"成果计价"兴起——**你收的钱，跟着客户获得的价值走**。

成果计价的四档进化链（越往上越贴近价值，也越难执行）：

| 档位 | 计价方式 | 难点 |
| --- | --- | --- |
| 按用量 | 模型调用量、处理量 | 清晰可测，但追踪的是成本不是价值 |
| 按行为 | 完成一次退货处理、生成一份报告 | 计价单位开始有业务含义 |
| 按结果 | 成功解决的会话、追回的坏账 | 归因需要双方认可的判定标准（评估体系在这里同时是计费基础设施） |
| 按价值分成 | 为客户创造的财务价值提成 | 需要客户开放财务数据和极强信任，目前只在少数深绑定场景出现 |

- 标杆（Sierra）：按"已解决的会话"收费，客户数据——Funnel 自助解决率 94%、Ramp 90%、Casper 74%；年合同门槛约 15 万美元起。**客户每一分钱都对应一次"问题真的被解决了"——敢这么收，是因为评估体系能向客户证明"解决了"。计价方式和评估体系是同一块硬币的两面。**
- 判断原则：**计价单位越贴近客户价值，定价天花板越高，但测量与信任成本也越高**。
- 中国注脚：国内客户对订阅制接受度有限，"买断 + 实施"仍是主流。可行的中西合璧：**按阶段交付验收（顺应项目制习惯）+ 价值指标写入验收标准（注入成果计价基因）**。纯订阅制是理想，混合制是活路。

### 6.4 存量深耕：从一个部门到一张大网

- 企业市场铁律：**最大的收入增长不在新客户，在老客户内部**（优秀 FDE 公司净收入留存常年 120% 以上）。
- "登陆与扩张"的三个方向：
  1. **横向**：从一个团队到相邻团队——弹药是"内部案例"（同公司、同数据环境、隔壁同事现身说法），几乎不需要重新建立信任。
  2. **纵向**：从执行层到决策层——为中层做分析预警，为高管做决策驾驶舱。意义不只是收入更是安全：**只被基层喜爱的系统，在预算季没有辩护者**。
  3. **纵深**：从辅助工具到核心流程——从"给建议"到"执行业务动作"、从"可选"到"标准作业流程的一部分"。替换一个工具只要换软件，替换一个嵌入流程的系统等于做一次手术——最深的护城河。
- 节奏纪律：**扩张必须由价值牵引，而不是由销售指标牵引**。客户组织里"看到别人用得好、主动来问"的时刻是扩张的黄金窗口——此时你不是在推销，是在响应需求。

### 6.5 Anthropic × FIS 案例：本章方法论的全演示

2026 年 Anthropic 与金融科技巨头 FIS 共建金融犯罪侦测智能体，四个动作环环相扣：

1. **嵌入而非交付**：工程师直接嵌入 FIS 共同设计——FIS 不是终端客户而是渠道级伙伴（智能体将随 FIS 的产品进入它背后数百家银行，一单生意是一百单的入口）。
2. **知识转移作为卖点**：合同写明"让 FIS 未来能独立构建和扩展自己的智能体"——把"教会客户"写进合同，既预防"供应商锁定"的质疑，也是高级绑定。
3. **可审计性作为产品特性**：每个智能体决策全程可回放——金融监管场景里，**别人眼里的合规成本，可以是你的定价理由**。
4. **生态放大**：单个案例立即抽象为可复制的产品资产（连接器 + 拿来即用模板）。
- 本案例的暗线警告（买方视角）：**前置部署的成本到底谁在付——这是首席信息官该问、但大多没问的问题**。你创造的价值必须持续大于你的存在感带来的成本与依赖。**赚价值的差价，生意长久；赚依赖的租金，迟早反噬。**

### 6.6 变惩为奖：用量与扩容的定价心理学

- 灾难场景：合同内用量用尽后按惩罚性高价计费或直接限流——客户为不超额而压抑使用，使用率下降、价值缩水、续约双输。**你惩罚的，正是你最想要的东西：深度使用。**
- 三个"变惩为奖"手法：
  1. **阶梯价格，越用越便宜**：客户看到的不是"用多了要多付"，而是"用多了单价更低、我们更划算了"。
  2. **超量预警 + 主动升舱**：监测到将超量时主动上门："照这个趋势，升一档套餐能省 15%。"把计费事件转化为顾问式销售机会。
  3. **把"省下来"的功劳还给客户**：主动汇报"这个季度通过架构优化为你们省了约 X 万元"——主动帮客户省钱的供应商与等着客户超量的供应商，是两种物种。
- 底层道理：**计价结构每天都在向客户讲述"我们是什么样的关系"**。惩罚式结构讲"我们盯着你"，奖励式结构讲"我们和你一起长大"。

### 6.7 建立价值度量系统

本章收尾的基础设施工程：**把"我们为客户创造了多少价值"从印象变成数据，从数据变成资产**。

- 四个层次的功能：对客户是续约与扩容的弹药库；对公司是交付质量的体检仪（哪类场景价值密度最高、哪类客户交付成本最高）；对产品是回流情报的放大器；对市场是信任营销的素材库（"化学品使用减少 70%"这类数字全部来自这套系统的积累——**案例营销的最高境界不是讲故事，是亮数据；而数据不会在谈判桌上凭空出现，它在交付第一天就要开始采集**）。
- 三条实践建议：
  1. **从第一天就采集基线**——没有改造前的基线数据就没有改造后的价值证明，而基线只在项目启动那一刻存在，**错过永不再来**；
  2. **度量指标必须与客户共建**——客户不认的指标，算出花来也没有谈判效力；
  3. **克制指标数量**——每个客户 3 到 5 个核心指标足矣，指标通胀的结果是没有指标被真正关注。

### 本章小结

- 免费验证三本账：销售费用换工程师费用、风险换定价权、失败也要沉淀资产；前提是毕业制。
- 转付费五开关：毕业标准、免费边界、武装支持者、提前埋锚点、体面出口。
- 成果计价四档（用量→行为→结果→价值分成）；中国市场用混合制落地。
- 存量深耕三方向（横向/纵向/纵深），由价值牵引不由销售指标牵引。
- 定价心理学：变惩为奖；价值度量系统从第一天采集基线。
- 核心结论：**FDE 模式的收入不是销售的战利品，而是价值的影子——你创造的价值越大，影子越长**。

## 第 7 章 规模化复制

> 「如果你不把现场学习转化为产品资产，你得到的只是一堆定制项目。」——Barry，前 Palantir 前置部署工程师

### 7.1 用可复制性撬动交付的杠杆

- 本章命题：**让一次交付，让下一次交付更容易**——交付引擎从堆人变成复利。
- 为什么是"最后一公里"：前面六章的打法如果抽掉本章内容，结局就是一支能打硬仗的精英团队接一个客户交付一个客户——**收入增长与人数增长完全线性。恭喜，你重新发明了咨询公司。**
- 两个试金石：
  - Barry 版："不把现场学习转化为产品资产，你得到的只是一堆定制项目。"
  - 麦格鲁版："每个后续客户的定制量递减"——定制量不随客户数递减，你就不是在做 FDE，是在做人天生意。
- 三级复制杠杆（一级比一级难，也一级比一级值钱）：
  1. **知识复制（打法手册）**：把"怎么做"写成文档——新人上手周期从一年压到三个月。多数团队止步于此。
  2. **组件复制（工具与代码）**：把"做过的"变成"能直接用的"——连接器、评估框架、部署模板。
  3. **产品复制（平台能力）**：把"反复出现的定制"抽象为平台标准能力——从此这个需求不再需要工程师到场。**前两级降低交付成本，第三级消灭交付成本。**
- 麦格鲁"砾石路与高速公路"比喻的完整版：FDE 修砾石路（解决眼前问题），组件团队铺碎石路基（让下一辆车好走），平台团队浇高速公路（从此人人可通行）。

### 7.2 坏事传千里：失败部署的复盘传播

- **失败是复制的原材料，掩盖失败的组织，等于把金矿当垃圾埋掉。**
- 三个机制：
  1. **复盘的无罪化**：复盘会议唯一规则"对事不对人"。一旦复盘与绩效挂钩，人们就开始修饰失败——修饰过的失败毫无教学价值。一个诚实复盘的失败项目负责人，对组织的贡献可能大于一个侥幸成功的。
  2. **教训的结构化**：复盘产出不能是"下次注意"式感慨，必须可检索、可执行（这类客户的高危信号、哪个集成假设被推翻、哪个评估指标设计错了），进入打法手册的"雷区"章节。**失败只有写进流程，才算真正被吸取。**
  3. **失败的适度外传**：脱敏后对外分享失败教训是极高效的信任营销——"我们已经为这个行业的弯路付过学费了"正是企业客户最想听到的。

### 7.3 借势而上：站在行业的风口上

- 2025–2026 的风口由三股气流汇成：95% 失败率成为企业信息主管的心病（心病就是市场）；OpenAI 与 Anthropic 同日成立部署公司把"部署"推上头条；FDE 岗位 800% 招聘增长让"要不要招 FDE"成为企业焦虑。罕见局面：**客户主动在找你，讨论你想卖的东西**。
- 三层借势动作：
  1. **定义议题**：把打法手册、失败复盘、价值度量数据产品化——独家一手认知是议题定义权的唯一货币。
  2. **绑定行业议程**：企业人工智能采购的驱动力正从"效率"升级为"生存"——把方案翻译成"董事会语言"："我们能让你在下次董事会上，拿出可量化的人工智能成绩单。"
  3. **在风口期建立资产，而不是消耗风口**：风口过去后，裸泳者退潮，有资产者上岸。

### 7.4 构建客户体外的传播循环

三个圈层的飞轮（交付创造故事 → 故事在圈层传播 → 传播带来新机会 → 新机会创造新故事）：

1. **从业者社区**：为新兴职业共同体贡献内容（方法论、工具、数据），你的名字就会与这个职业绑定。
2. **客户的行业社区**：进入封闭圈层的门票不是广告，是**被邀请演讲的客户支持者**——客户在他的行业峰会上替你做的十分钟分享，胜过你在一百天展位。
3. **生态伙伴网络**：云厂商架构师、咨询顾问、集成商项目经理每天在不同客户现场流动。经营要点是让他们"赢"——**帮别人成功的人，会被整个网络记住**。

### 7.5 产品内置的裂变因子

让交付的系统自己成为扩张的推销员，四个因子：

1. **可见性设计**：让输出物携带"出身"——报表页脚"由某某系统生成"、异常预警里的处理入口链接。漂亮的分析报告被转发给隔壁部门总监时，看到的人自然会问"这是什么做的"。
2. **协作式准入**：设计需要跨角色协作的功能（调查官标注的案例需要主管复核）——协作带来的新用户不是"被推广的"，是"被工作本身带来的"。
3. **自助化的探索层**：在核心交付之外留一个低风险沙盒，让客户员工自己试——**让全民帮你做发现，让 FDE 做攻坚**。（2026 年新趋势：Sierra 的 Ghostwriter 让客户上传流程文档自动生成智能体；Decagon 让客服主管用自然语言写流程——**当客户开始自己建造，你的角色就从建筑队变成了设计院**。）
4. **跨边界的价值证据**：每季度自动生成"本季度价值报告"，让它自然流向客户高管层。
- 共同原则：**扩散必须寄生在真实的业务价值上**——企业市场没有病毒式传播，只有"口碑的链式反应"：慢，但每一步都坚实。

### 7.6 规模化中的组织政治把握

- 规模化的最大障碍从来不是技术，而是人的地盘：信息垄断被打破、审批权被压缩、专业壁垒被夷平——每一个变化都在制造沉默的敌人。
- 三条心法：
  1. **扩张必须带着"当地人"**：每进一个新部门，先找那个部门最有声望的资深员工，邀请他参与适配。**人们不会反对自己参与建造的东西**——组织行为学里最可靠的杠杆。
     - 经典教案（Harvey 在律所）：所内三层人群——合伙人（买单但不干活）、律师助理（干活但不签字）、知识管理律师（看得到两边盲区）。为三层人分别设计访谈和演示：给合伙人看"这单生意多赚钱"，给助理看"这周少加三天班"，给知识管理律师看"全所的隐性经验终于有地方沉淀"。**一个部署要同时让三层人都觉得自己是受益者。**
  2. **让每一步扩张都有"受益者"**：被穿透数据壁垒的部门，得到了全局可见的分析能力。**没有受益者的扩张是侵略，有受益者的扩张是解放**——区别只在于你有没有把"他得到什么"想明白、讲清楚。
  3. **永远给"旧秩序"留体面**：被系统替代的流程曾也是某个能干的人设计的。话术示例："这套流程在过去十年支撑了公司，现在我们要把它十年的经验，放大一百倍。"**被善待的旧世界，才不会在新世界里捣乱。**

### 7.7 用打法手册沉淀复制效率

多数团队的打法手册写成"写完即死"的文档坟场，有效的手册有三个属性：

1. **长在流程里，而不是躺在知识库里**：新项目尽调阶段自动弹出该客户类型的尽调清单；部署阶段检查清单是任务系统里的硬关卡；复盘阶段手册更新是必填产出。**知识不嵌入流程，就只是考古资料。**
2. **按"场景"而非"功能"组织**：不按公司组织结构写（"交付流程""技术规范"），按客户场景写（"金融反洗钱场景打法""制造业排产场景打法"）。每个场景手册的固定七件套：
   - 典型痛点与契合检验要点；
   - 尽调清单（这个场景特有的高危信号）；
   - 数据与集成的已知雷区；
   - 评估与验收的指标模板；
   - 变革管理的角色地图；
   - 计价与扩容的参考结构；
   - 历史复盘的教训库。
3. **必须"活"**：有负责人、有版本、有折旧——每个场景手册指定负责人，每个项目结束强制回看更新，每半年整体检修。**没有负责人的手册，会在一年内腐烂成误导新人的陷阱，比没有手册更糟。**
- 三级资产的关系：**手册记录"判断"，组件库沉淀"手艺"，平台固化"能力"**。三者齐备，一支新组建的 FDE 小队能在两周内达到老团队八成战斗力。

### 7.8 产品化的策划与打磨

把现场经验结晶为产品——FDE 模式的炼金术。最壮观的成功案例：Palantir 的 Foundry 核心组件诞生于苏黎世、休斯顿、圣保罗、图卢兹等客户现场，自下而上长成年收入数十亿美元的平台。

**产品化四问**（收编一个现场解法前的检验清单）：

1. **是"个性"还是"共性"？** 同类问题是否在三个以上客户那里独立出现过？三个客户的相同痛点是产品信号，一个客户的特殊要求可能只是怪癖。
2. **泛化的代价是否小于收益？** 现场代码"快而糙"，泛化成本"往往高于写第一版"。算不过来的留在组件层，不要强行平台化——**平台里的每一个能力，都是终身维护承诺**。
3. **能否被"不会写代码的人"使用？** 产品化最难的一步往往不是技术而是交互——把工程师的脚本变成业务人员能配置的功能。
4. **收编之后，现场还有空间吗？** 收编太多，现场团队退化为配置员，FDE 模式的灵魂（现场创造力）就死了；收编太少，规模化杠杆起不来。Palantir 的解法是"前线对基地的激进授权"：**平台负责让"常见的事容易"，现场负责让"不可能的事发生"**。

**关于毛利率的历史证据**（回应"派人下现场毛利怎么可能高"）：ServiceNow 上市时毛利率 63.2% → 十年后 79%；Workday 54.1% → 76%；Palantir 上市时 79% → 2025 年 82%。秘诀是**毛利率的爬坡机制**：随着平台沉淀加厚、客户自己能干的实施工作越来越多（训练营模式让大量集成由客户侧完成），服务成本被持续摊薄。**先丑后美，先重后轻。**

### 本章小结

- 规模化复制是 FDE 与咨询公司的最后一道防线：三级杠杆 = 手册（知识）→ 组件（手艺）→ 平台（能力）。
- 失败是复制的原材料：无罪化复盘、结构化教训、适度外传。
- 扩散寄生在真实价值上：可见性设计、协作式准入、自助探索层、价值报告；没有病毒式传播，只有口碑的链式反应。
- 组织政治三心法：带当地人、每步有受益者、给旧秩序留体面。
- 打法手册三属性：嵌流程、按场景组织（七件套）、必须活（负责人 + 版本 + 折旧）。
- 产品化四问：共性？泛化划算？不会写代码的人能用？现场还有空间？
- 终极公式：**现场是探针，平台是杠杆，产品是复利的载体**。

## 第 8 章 完整案例集

本章把前七章方法论还原到真实现场，五组案例的精华如下。

### 8.1 Palantir：用二十年把一个"笨办法"炼成护城河

- **创业**（2003）：为"不能问的用户"（情报机构）造软件 → 发明演示循环。
- **成型**：桑卡尔的关键一跃——"不做两个产品，也不做一个僵化的产品，而是做一个高度可定制的平台 + 派工程师驻场修最后一公里"；把定制从"服务成本"重新定义为"产品发现"。
- **组织形态**："回声"（部署战略师，理解客户使命）+"三角洲"（前置部署工程师，技术实现）+ 平台工程师三角分工。2016 年前 FDE 人数超过产品工程师。
- **试炼现场**：伊拉克路边炸弹地图工具（不可能诞生于任何总部会议室）、保密室两周驻场（电话绑头上每天 19 小时）、飓风桑迪救灾、空客 A380 燃油泵两周破案。
- **代价的真实账本**（Barry 记录）：顶尖工程师、全球差旅、大量重复造轮子、免费试点、"很多项目利润率字面是负无穷"。Palantir 吞下代价靠两样：天价合同撑起的资本厚度 + "试点即风投组合"的心智。
- **爆发**：AIP 训练营把二十年驻场方法论压缩成工业化机器——2025 年高峰日均近 6 场，销售周期从九到十二个月压到数周。
- **最大的信任票**：美国海军 4.48 亿美元"造船操作系统"合同（潜艇排产从 160 小时到 10 分钟；物料审核从几周到一小时），海军部长特意声明"这不是概念、不是试点、不是研究"。
- **方法论还原**：Palantir 案例几乎是全书索引——演示循环（第 2 章）、定制即产品发现（第 1、7 章）、灯塔战略（第 3 章）、免费试点组合投资（第 6 章）、现场工具自下而上长成平台（第 7 章）、复杂性无法被远程消灭必须有人到场（全书）。

### 8.2 OpenAI：当造出 ChatGPT 的人开始下场搬砖

- **转折**（2024）：模型能力趋同、企业市场份额变动，客户用真金白银投票的标准变成"谁能帮我把这东西真正用起来"。
- **两步回应**：组建 FDE 团队（一年从 2 人到 52 人，遍布全球十城）；2026 年成立"部署公司"（OpenAI 控股、联合 19 家顶级资本、初始投资超 40 亿美元、投前估值约 100 亿美元，同步收购有 150 名部署工程师的咨询公司 Tomoro）。
- **部署公司的资本结构创新**：出资方是私募股权巨头，它们手里的几百家被投企业就是现成客户池——**把"客户从哪来"和"资本怎么回"焊在了一起**。
- **现场一（约翰迪尔）**：本书第 2、4 章方法论的完整演示——下田影子工作、评审数百个真实案例建评估体系、在评估看护下迭代模型；三个划线细节：**死线是农时而非项目排期；评估体系先于模型优化；70% 是开工前定好的靶子**。
- **现场二（西班牙对外银行）**：从 3300 账号到 12 万人的组织化路径——起点是工具，路径是组织，终点是"人工智能原生的全球银行"。
- **启示**：当模型能力趋同，部署能力成为差异化主战场；当产品形态未定，现场成为产品发现的唯一现场。

### 8.3 Anthropic 与垂直三杰：FDE 的三种变奏

- **变奏一（Anthropic）**：安全基因做成差异化——"可审计、可追溯"成为产品特性（FIS 反洗钱智能体，调查从数小时到数分钟，每个决策可回放）；"知识转移"写进合同（教会 FIS 独立建智能体）；与埃森哲合作培训三万名顾问。**把"安全偏执"变成了企业市场的杀手锏**：别人眼里的合规成本，是它的定价理由。
- **变奏二（Sierra 与 Decagon）**：把 FDE 做成商业模式本身。
  - Sierra：按"已解决的会话"收费（成果计价最激进样本）；岗位命名"智能体工程师"。
  - Decagon：把交付经验直接产品化——客户的运营人员用自然语言定义多步工作流（Chime 自助解决率 70%、多邻国分流率 80%、ClassPass 客服成本降 95%）。
- **变奏三（Harvey）**：打进普通软件进不去的地方——法律行业保密纪律森严、数据不出域、合伙人各自为政。打法是全书方法论的完美串烧：灯塔战略（年利达）、支持者经营（韦克林）、纵深节奏（单一业务组切入六个月后横向扩张）、三层人群客户研究、超长周期（单所部署六到九个月）。
- Harvey 证明的边界：**凡是"保密制度、数据驻留、关键用户自主权"三座大山同时存在的市场，产品化交付无解，只有人进去，才能把系统带进去**——而这样的市场（法律、医疗、金融、政府）恰好是地球上利润率最高的企业服务市场。

### 8.4 中国案例：在"项目制"的土地上种 FDE

- 中国企业软件的三声叹息：定制化是 SaaS 的天敌；很多公司一两亿收入就卡住；"项目制的成本离场即作废，没法摊出去"。
- **大厂路径**：火山引擎成立豆包 FDE 团队（覆盖汽车、医疗、教育、金融、半导体），与安永共建千人级团队。先天优势是平台底座厚，先天挑战是"交付是成本中心"的财务惯性。
- **先行者路径**：本土创业公司把"FDE 不等于驻场外包"写进官网三句话——按阶段交付按结果验收 / 带着产品底座做工程 / 做完会走能力沉淀。还建立了"劝退机制"（场景未验证不接、数据一张表能导出不接、只想了解人工智能不接）。
- **中国 FDE 的三个特殊命题**：
  1. **计价之困**：可行过渡是混合制——按阶段验收付款 + 价值指标写入验收条款 + 年度运维合同。
  2. **平台之困**：大量中国公司"有现场、没平台"——比学 FDE 形式更重要的是先补地基：把最高频的定制沉淀为可复用组件。**没有复制杠杆，FDE 在中国只会沦为"名字好听的驻场外包"。**
  3. **人才之困与人才之机**：中国交付工程师文化（能吃苦、响应快、全栈通吃、习惯现场解决一切）最贴近 FDE 要求；FDE 概念的普及可能**重新为中国数十万交付工程师定价**。
- 判断：FDE 不会治愈中国企业软件所有痼疾，但提供了一次"正名"机会——**把"贴近客户"从低端外包的标志，重新定义为高端能力的标志**。

### 8.5 一个人工智能创业团队的 180 天（N 公司全复盘）

一份可直接对照执行的实战时间线（数字模糊化，比例关系真实）：

1. **第 1–30 天：选战场，而不是抢合同**。三个线索（头部券商/区域连锁零售/三甲医院）中放弃预算最大的券商（宇宙级需求 + 无业务负责人）和数据敏感的医院，选择痛点具体、首席财务官亲自盯项目的零售集团。**排期按战略价值与学习价值排，不按合同金额排。**
2. **第 31–75 天：进场、影子工作法、砍掉大方案**。前两周不写一行产品代码，跟着区域经理巡店。关键发现来自一个"变通"：经理们不信任公司数据系统（"数据晚三天还老错"），真正信任的是店长每天手填的表。最初的大方案（智能数据分析平台）被推翻，MVD 收窄为"**门店异常日报**"——每天早上八点把 3000 家门店异常信号汇总成三分钟读完的日报推到微信。真实数据、单一痛点、六周死线。
3. **第 76–120 天：激活的暗战**。两个教科书障碍及解法：误判促销高峰为异常 → 48 小时内接入促销日历 + **在群里公开致谢报错的经理**；资深区域总监冷眼旁观 → 请他参与评估标准修订、三条经验写进系统规则 → 两周后成了最卖力的布道者。第 90 天日报自然打开率稳定 85% 以上；第 120 天客户首席信息官在季度经营会上主动展示系统。
4. **第 121–180 天：复制的第一块砖**。沉淀零售行业数据接入组件、"异常信号"评估框架、门店场景尽调清单（第一份场景打法手册成型）；用可联合发布的案例敲开第二家同构客户，**第二个项目交付周期比第一个缩短 40%**——复制飞轮转出第一圈。
- 全案例的公式：**正确的问题 + 真实的数据 + 贴身的服务 + 沉淀的纪律 = 可以滚动的雪球**。

### 本章小结

- 五组案例跨度极大（情报机构到农田到律所到中国零售），方法论共性极其清晰——这本身就是方法论有效性的证明。
- 记住三个"不可能"：地图工具不可能诞生于总部会议室；从不见面的 FDE 是伪命题；三座大山市场只有人进去才能把系统带进去。
- N 公司 180 天复盘是最贴近普通团队的可操作模板。

## 后记 FDE 的职业道德

FDE 手里握着的是**客户组织最深处的秘密，和越来越大的、代替人做决定的权力**。六条底线：

1. **数据的主权属于客户**：一个字节都不该出现在不该出现的地方——不进训练语料（除非合同授权）、不进案例素材（除非书面同意）、不进你下一份工作的谈资。能不看的就不看，能脱敏的就脱敏。
2. **诚实报告结果，包括坏消息**：价值度量系统既可以是最诚实的工具，也可以是最精巧的谎言机器，区别只在人心。把"系统上线了"包装成"价值实现了"是最大的道德风险。
3. **不制造依赖，不贩卖恐惧**：不故意把系统做成黑箱，不夸大"不用人工智能就会死"的恐慌。**让客户强大，而不是让客户上瘾**——健康的 FDE 模式是"做完会走"。
4. **把"被替代的人"当回事**：不在被替代者面前庆祝效率、不把人写成"成本项"而不给出路、不对"正在改变谁的命运"装糊涂。
5. **对"客户要求但不该做的事"说不**：真正的专业不是满足一切要求，而是敢于引导客户走向对他真正有利、对世界无害的方向。（说不的底气来自账上有别的客户——**道德从来也和商业模式有关**。）
6. **记住你代表的是"技术"本身**：你是很多客户接触人工智能的第一张人脸——每一次夸大都在透支整个行业的信用，每一次兑现都在为整个行业存款。

## 附录 A FDE 应当关注的常用指标（速查表）

> 使用原则：指标贵精不贵多——每个客户项目盯 3 到 5 个核心指标，胜过铺满一面墙的仪表盘。

### 交付层（项目做得对不对）

| 指标 | 含义与水位 |
| --- | --- |
| **TTV（价值实现时间）** | 从进场到客户获得第一次可衡量价值的时间。MVD 应以周计（2–6 周），完整部署以月计（1–4 个月）。持续变长是方法论或平台出问题的第一信号 |
| **概念验证转化率** | 验证项目进入付费部署的比例（Palantir 训练营从 5%–10% 提到约 75%）。过低说明筛选失职；过高要检查是不是只接没挑战的单 |
| **评估达标率** | 人工智能输出通过业务评估集的比例及走势——质量漂移的报警器 |
| **部署频次与回滚率** | 迭代速度硬指标，健康状态是高频小步 + 低回滚 |
| **缺陷逃逸率** | 上线后才被发现的缺陷占比，测的是评估体系完备性 |

### 客户层（客户活得怎么样）

| 指标 | 含义与水位 |
| --- | --- |
| **激活率** | 目标用户群中形成稳定使用习惯的比例（分母是目标用户群，不是账号数） |
| **使用深度** | 功能渗透率、频次分布（打卡式还是工作流嵌入）、自助探索行为的出现（最珍贵的信号） |
| **健康度评分** | 使用 + 价值 + 关系 + 商业四类信号加权合成；每周全量巡视 |
| **支持者覆盖数** | 活跃盟友的数量与层级分布——单点是高危，三点成网 |
| **净推荐值（NPS）** | 企业场景慎用（样本小、政治化）；更可靠的是到期前两季度直接问支持者"今天续约你会续吗" |

### 商业层（生意值不值）

| 指标 | 含义与水位 |
| --- | --- |
| **NRR（净收入留存）** | 存量客户收入年度变化。及格线 100%，优秀线 120%——高于 120% 说明增长引擎已内生 |
| **交付毛利率** | 纯人力交付期可能只有 20%–40%，平台复用上来后应向 60%+ 爬坡。**爬坡速度比绝对值更能说明模式是否成立——不爬坡的 FDE 是咨询公司** |
| **定制递减率** | 第 N 个客户的定制量应显著小于第 1 个。连续三个客户不降，立即检视回流机制 |
| **销售周期** | Palantir 用训练营从 9–12 个月压到数周 |
| **CAC 回收期 / LTV/CAC** | 获客成本回收时间 / 客户终身价值与获客成本比（健康线 3 以上；FDE 早期可能低于 2，须配合 NRR 一起读） |

### 组织层（团队能不能走远）

| 指标 | 含义与水位 |
| --- | --- |
| **现场到产品回流速率** | 单位时间从现场沉淀为组件/平台能力的产出数——**测量 FDE 模式的"灵魂器官"是否还在跳动** |
| **交付资产复用率** | 新项目复用已有组件/模板/清单的比例，应逐季上升 |
| **FDE 人均产能** | 每名 FDE 支撑的年收入——规模化的总账 |
| **团队续航指标** | 出差强度、值班负荷、离职率。团队烧干了，前面所有指标都是烟花 |

### 指标使用四原则

1. 每个项目锁定 3–5 个"北极星组合"：通常一个价值指标 + 一个使用指标 + 一个关系指标。
2. 基线数据项目启动第一天采集——**错过永不再来**。
3. 指标与客户共建、双方共认，否则在续约谈判桌上没有效力。
4. 每半年检修指标体系本身：删除无人看的，补上反复被问的。

## 可直接执行的清单汇总

**进场前（对应第 2–3 章）**：

1. 三关检验：痛点（具体的人的具体痛）→ 经济性（算得清账）→ 可行性（数据现实 + 准确率门槛）；
2. 三类高危信号扫描：无业务负责人？拒给真实数据？宇宙级需求？
3. 写毕业标准：多少周、什么指标、达到什么数值进付费，达不到体面散伙；
4. 画五张地图：数据（哪个被信任）、流程（三个富矿点位）、组织（知识枢纽）、系统（变更流程）、政治（谁受损）。

**进场后（对应第 4 章）**：

1. 影子工作法观察变通，绕过翻译过的痛点；
2. MVD 三军规：真实数据、砍范围不砍价值、周级死线；
3. 环境策略读旧写新：数据兼容、架构不寄生、顺从人的习惯；
4. 评估体系三步：真实案例长出来 → 业务方当评委 → 接生产回路；
5. 热修复节奏：反馈零中间层、按使用阻塞度排序、每天收工问"明天的哪一刻更顺了"。

**稳住与放大（对应第 5–6 章）**：

1. 每周巡视健康度四信号（使用/价值/关系/商业）；
2. 关系网格化：一个支持者 + 两条独立关系线；
3. 把系统嵌入客户流程文件（最强制度性锁定）；
4. 从第一天采集价值基线，每个客户 3–5 个共建指标；
5. 转付费五开关提前设计：毕业标准、免费边界、武装支持者、埋价格锚点、体面出口。

**沉淀复制（对应第 7 章）**：

1. 每个第二次做的动作问一句"能变成脚本/模板/清单吗"；
2. 失败复盘无罪化 + 教训结构化写进手册雷区；
3. 按场景写打法手册七件套，指定负责人、每半年检修；
4. 产品化四问决定是否收编为平台能力；
5. 盯定制递减率：连续三个客户不降，立即检视回流机制。
