ChatGPT、Claude、DeepSeek、RAG、Agent、MCP、向量数据库……打开任何一篇 AI 资讯，这些词总是扎堆出现。它们到底是什么、谁依赖谁、怎么拼在一起工作？这篇文章把主流概念一次性梳理清楚，帮你在 15 分钟内建立一张完整的「AI 技术地图」。

> 阅读姿势：不用死记定义。重点看每个概念**解决什么问题**、**依赖什么**——关系理顺了，认知框架自然就有了。

## 一、地基：大语言模型（LLM）

**大语言模型（Large Language Model, LLM）** 是整个 AI 应用生态的地基。你可以把它想象成一个「读遍了几乎整个互联网文字」的超级文字接龙机器：给它一段开头，它就预测接下来最合理的文字。

- **通俗理解**：一个见多识广的「下一句预测器」。因为读得足够多，预测得足够准，看起来就像「理解」了世界。
- **主流代表**：OpenAI 的 GPT 系列、Anthropic 的 Claude、Google 的 Gemini、DeepSeek、阿里 Qwen（通义千问）、Meta 的 Llama 等。
- **关键限制**：它只知道训练时「读过」的东西（有知识截止日期）；会一本正经地胡说八道（幻觉）；天生不会主动做任何事，只会「回答」。

**后面几乎所有概念，本质上都是在「补 LLM 的短板」。** 记住这句话，下面的地图就好读了。

## 二、地基的扩展：多模态模型

**多模态模型（Multimodal Model）** 是 LLM 的「感官升级版」：除了文字，还能看图片、听音频、看视频。

- **通俗理解**：从「只会读书的学霸」变成「能看图、能听声的全科选手」。
- **主流代表**：GPT-4o / GPT-5 系列、Gemini、Qwen-VL、Claude 等，现在的一线模型基本都是多模态的。
- **与 LLM 的关系**：多模态模型可以理解为 LLM 的超集——文字能力仍是核心，额外接上了视觉、听觉等「输入通道」。

## 三、用好模型的三板斧：提示工程、RAG、微调

同一个模型，用法不同效果天差地别。让模型「更懂你」有三条主流路径，从轻到重依次是：

### 1. 提示工程（Prompt Engineering）——「把话说清楚」

**提示工程**就是研究怎么向模型提问，让它给出更好的答案。

- **通俗理解**：跟聪明人打交道，问题问得越清楚，答案越靠谱。给角色、给背景、给示例、给格式要求，都算提示工程。
- **依赖关系**：只依赖 LLM 本身，零成本，人人可上手。
- **常见技巧**：系统提示词（system prompt）、少样本示例（few-shot，给它几个范例照着学）、思维链（chain-of-thought，让它一步步推理）。

### 2. RAG（检索增强生成）——「开卷考试」

**RAG（Retrieval-Augmented Generation，检索增强生成）**：先从你的资料库里检索出相关内容，再让 LLM 参考着这些内容回答。

- **通俗理解**：闭卷考试模型容易瞎编，RAG 就是给它「开卷考试」——先翻书（检索），再答题（生成）。完美解决「知识截止」和「不了解你的私有数据」两大痛点。
- **依赖关系**：**RAG = 向量数据库（管检索）+ LLM（管生成）**。这是本图里最重要的一条依赖线。
- **典型场景**：企业知识库问答、文档助手、客服机器人。

### 3. 微调（Fine-tuning）——「送模型去上培训班」

**微调**是用你自己的数据继续训练一个现成模型，让它在特定领域表现更好。

- **通俗理解**：模型是「通才」，微调就是送它去上专项培训班，变成你要的「专才」。常配合 **LoRA** 等轻量技术，只调一小部分参数，成本低很多。
- **依赖关系**：微调改变的是 **LLM 本身**（模型权重），而提示工程和 RAG 都不动模型。
- **与 RAG 怎么选**：想让模型「知道新知识」→ 优先 RAG；想让模型「换风格/学套路」（比如固定口吻、专业术语体系）→ 考虑微调。实践中常常两者结合。

## 四、从「会聊天」到「会干活」：智能体（Agent）

前面的概念都还是「你问我答」。**智能体（Agent）** 是让 AI 从「顾问」变成「员工」的关键跃迁。

**智能体 = LLM（大脑）+ 工具调用（手脚）+ 记忆（笔记本）+ 自主规划循环（自己安排做事步骤）**

- **通俗理解**：普通 LLM 对话像「问路」——只能告诉你怎么走；智能体像「代驾」——自己规划路线、自己开车、办完事还向你汇报。
- **工作循环**：接到任务 → 拆解步骤 → 选择工具 → 执行 → 观察结果 → 调整计划 → 循环直到完成。
- **依赖关系**：**智能体依赖 LLM（推理决策）+ 工具调用（执行动作）**，RAG 和记忆负责给它「补给信息」。
- **典型场景**：自动写周报并群发、监控数据异常并排查、自动订机票酒店、批量处理文件——本文站点就是我用一个智能体（WorkBuddy）从零搭建并发布到 GitHub Pages 的。

### 4.1 工具调用（Tool / Function Calling）——「给 AI 装上手」

**工具调用**是让模型能执行真实动作的机制：开发者预先告诉模型「有哪些工具可用、各需要什么参数」，模型在需要时输出结构化的调用请求，由外部程序真正去执行。

- **通俗理解**：模型本身只会「说话」，工具调用让它能「动手」——查数据库、发邮件、调 API、操作浏览器。
- **依赖关系**：工具调用是**智能体的执行基础**，没有它智能体只能空谈。

### 4.2 MCP（Model Context Protocol）——「AI 世界的 USB-C 接口」

过去每接一个工具，开发者都要为「模型 ↔ 工具」单独写一层胶水代码，工具一多就是灾难。**MCP** 是 Anthropic 在 2024 年底提出的开放协议，2025—2026 年已成为事实行业标准，把「模型连接外部世界」这件事标准化了。

- **通俗理解**：以前每个设备一种充电口，MCP 就是「USB-C」——工具按 MCP 标准封装一次，任何支持 MCP 的模型/智能体都能即插即用。
- **依赖关系**：**MCP 是工具调用的标准化封装层**。工具调用解决「能不能动手」，MCP 解决「动手的方式是否统一、可复用」。
- **生态现状**：GitHub、数据库、浏览器、地图、邮件、文档办公等数以千计的 MCP 服务端已经出现，主流智能体框架普遍原生支持。

## 五、幕后支撑：向量数据库与推理框架

这两个概念不常出现在新闻标题里，但缺了它们，上面的东西都跑不起来。

### 5.1 向量数据库（Vector Database）——「语义图书馆」

文本可以经过 **Embedding 模型**转换成一串数字（向量），语义越接近的文本，向量距离越近。**向量数据库**就是专门存储、检索这些向量的数据库。

- **通俗理解**：传统搜索靠「关键词匹配」，向量检索靠「意思相近」。你说「怎么让电脑跑快点」，它能把「清理磁盘垃圾提升性能」的文档也找出来。
- **主流代表**：Milvus、Qdrant、Chromadb、FAISS，以及 PostgreSQL 的 pgvector 插件。
- **依赖关系**：**向量数据库是 RAG 的检索底座**，同时也常被用作智能体的「长期记忆」存储。

### 5.2 推理框架（Inference Framework）——「模型的发动机」

训练好的模型要「跑起来」才能服务用户，负责高效运行模型的软件就叫**推理框架**。

- **通俗理解**：模型是发动机图纸，推理框架是造好的发动机——决定跑多快、烧多少油（显存）、能同时载多少客人（并发）。
- **主流代表**：vLLM（高吞吐服务首选）、llama.cpp / Ollama（个人电脑本地跑模型）、SGLang、TensorRT-LLM。
- **依赖关系**：推理框架在**最底层支撑一切**——不管你做 RAG 还是智能体，总得有个东西把模型跑起来。与之配套的**量化（Quantization）**技术能压缩模型体积，让大模型跑进消费级显卡甚至笔记本。

## 六、全景关系图：谁依赖谁

把上面所有概念串成一张图（自下而上看）：

```
┌─────────────────────────────────────────────────────────┐
│  应用层    智能体（Agent）                                 │
│            ＝ LLM（大脑）＋ 工具调用（手脚）                │
│            ＋ 记忆（RAG/向量库）＋ 规划循环（自主性）        │
├─────────────────────────────────────────────────────────┤
│  连接层    MCP ── 标准化「工具调用」，让工具即插即用          │
│            工具调用 ── 模型执行真实动作的机制                │
├─────────────────────────────────────────────────────────┤
│  增强层    RAG ── 检索增强生成                             │
│            提示工程 ── 不改模型，只优化「怎么问」            │
│            微调 ── 改模型本身，训练出「专才」               │
├─────────────────────────────────────────────────────────┤
│  模型层    大语言模型（LLM）←── 多模态模型（感官扩展）       │
│            Embedding 模型（文本→向量，供检索用）             │
├─────────────────────────────────────────────────────────┤
│  基础设施  向量数据库（RAG 与记忆的底座）                    │
│            推理框架（把模型高效跑起来的发动机）               │
└─────────────────────────────────────────────────────────┘
```

再用一张表快速对照「每个概念靠什么成立」：

| 概念 | 一句话解释 | 依赖什么 | 被谁依赖 |
|---|---|---|---|
| LLM | 超级文字接龙机器 | 训练数据、算力 | 几乎所有上层概念 |
| 多模态模型 | 能看图听声的 LLM | LLM | 上层应用（看图问答等） |
| 提示工程 | 把问题问好 | LLM | RAG、智能体 |
| RAG | 开卷考试 | **向量数据库 + LLM** | 智能体（记忆/知识） |
| 微调 | 专项培训改造模型 | LLM + 领域数据 | 特定领域应用 |
| 工具调用 | 给模型装上手 | LLM | **智能体、MCP** |
| MCP | 工具连接的 USB-C | 工具调用 | 智能体生态 |
| 向量数据库 | 语义图书馆 | Embedding 模型 | **RAG、智能体记忆** |
| 推理框架 | 模型发动机 | 模型权重、硬件 | 所有在线服务 |
| 智能体 | 会自主干活的 AI 员工 | **LLM + 工具调用 + 记忆** | 最终用户 |

## 七、协同工作实例：一次请求的完整旅程

概念单独看都抽象，串起来看就活了。假设你对一个智能体说：**「总结一下上周 AI 领域的重要新闻，发到我的邮箱」**，背后会发生什么——

1. **推理框架**先把 LLM「跑起来」，随时待命（发动机点火）；
2. **智能体**的大脑（LLM）接到任务，规划步骤：先搜集新闻 → 再筛选总结 → 最后发邮件（自主拆解）；
3. 通过 **MCP** 标准接口调用「网页搜索」「RSS 抓取」等**工具**，拿到原始新闻（动手干活）；
4. 需要参考你上周的关注偏好时，从**向量数据库**里语义检索你的历史记录（相当于 RAG 开卷）；
5. LLM 综合所有信息生成日报（**提示工程**决定了总结的格式与风格）；
6. 再通过 MCP 调用「邮件」工具发送，完成后向你汇报（闭环）。

一条指令，十个概念各司其职。这就是它们协同工作的样子。

## 八、给新手的学习路径建议

按依赖关系自底向上学，事半功倍：

1. **先玩透 LLM 对话**：日常高频使用，练**提示工程**（零成本、见效最快）；
2. **动手搭一次 RAG**：用 Ollama 本地跑个小模型 + 一个向量数据库，做一个「问答自己的文档」玩具，RAG 和向量检索一次搞懂；
3. **体验智能体**：用一个现成的智能体产品（或框架）完成一件真实小事，观察它如何规划、调用工具；
4. **按需深入**：想做服务看 vLLM，想做行业应用研究微调/LoRA，想做集成了解 MCP 开发。

不必追求一次吃透所有细节。记住这张地图的骨架——**LLM 是大脑，工具调用是手脚，MCP 是标准接口，RAG + 向量数据库是记忆与知识，推理框架是发动机，智能体把它们组装成一个能自主干活的员工**——以后再看到任何新名词，先问一句「它在地图的哪一层、依赖谁」，就能迅速归位。

祝你在 AI 世界里玩得开心。
