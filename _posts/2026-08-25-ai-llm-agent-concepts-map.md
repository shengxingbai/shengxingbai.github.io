ChatGPT、Claude、DeepSeek、RAG、Agent、MCP、Codex、Claude Code、Marvis、WorkBuddy、Context Engineering、FDE……打开任何一篇 AI 资讯，这些词总是扎堆出现。它们到底是什么、谁依赖谁、怎么拼在一起工作？这篇文章把主流概念一次性梳理清楚，帮你在 20 分钟内建立一张完整的「AI 技术地图」。

> **阅读姿势**：不用死记定义。每个概念统一按三段式展开——**是什么**（一句话定义）、**用来做什么**（典型场景）、**与其他概念的关系**（上下游与易混淆点）。重点看每个概念**解决什么问题**、**依赖什么**——关系理顺了，认知框架自然就有了。

## 一、模型家族：AI 世界的「大脑们」

### 1.1 大语言模型（LLM）——一切的地基

- **是什么**：大语言模型（Large Language Model，LLM）是一个「读遍了几乎整个互联网文字」的超级文字接龙机器——给它一段开头，它预测接下来最合理的文字。因为读得足够多、预测得足够准，看起来就像「理解」了世界。
- **用来做什么**：写作、翻译、总结、问答、写代码、头脑风暴——凡是「输入文字、输出文字」的事它都行。主流代表有 OpenAI 的 GPT 系列、Anthropic 的 Claude、Google 的 Gemini、阿里 Qwen（通义千问）、Meta 的 Llama 等。
- **与其他概念的关系**：后面几乎所有概念，本质上都是在**补 LLM 的三大短板**——知识有截止日期、会一本正经地胡说（幻觉）、天生只会「回答」不会「做事」。记住这句话，整张地图就好读了。

### 1.2 多模态模型——给大脑装上眼睛和耳朵

- **是什么**：多模态模型（Multimodal Model）是 LLM 的「感官升级版」：除了文字，还能看图片、听音频、看视频。
- **用来做什么**：看图说话、识票据、读表格截图、理解语音指令——典型如 GPT-4o/GPT-5 系列、Gemini、Qwen-VL、Claude，如今一线模型基本都是多模态的。
- **与其他概念的关系**：可以理解为 **LLM 的超集**——文字能力仍是核心，额外接上了视觉、听觉等「输入通道」。它和 LLM 同处地图的**模型层**，是更高级的「大脑」。

### 1.3 DeepSeek——开源高性价比的代表选手

- **是什么**：DeepSeek 是一家中国 AI 公司（深度求索）及其开源大模型家族的名字，以「性能对标一线闭源模型、价格只有零头」著称。
- **用来做什么**：日常对话、写代码、推理任务，尤其适合**预算有限又想要强模型**的团队和个人；因为开源（开放权重），可以自己下载部署，数据不出内网。
- **与其他概念的关系**：DeepSeek 是 **LLM 家族中的一员**，代表「开源阵营」；正因为开源，它常被搭配 **推理框架**（如 vLLM、Ollama）在本地或私有服务器上跑起来，也是 Marvis 等产品云端可选的模型之一。与「ChatGPT 是不是就是 DeepSeek」这类混淆要说清：前者是 OpenAI 的闭源产品，后者是开源模型家族，定位不同。

## 二、用好模型的三板斧：提示工程、RAG、微调

同一个模型，用法不同效果天差地别。让模型「更懂你」有三条主流路径，从轻到重依次是：

### 2.1 提示工程（Prompt Engineering）——「把话说清楚」

- **是什么**：研究怎么向模型提问、让它给出更好答案的方法。给角色、给背景、给示例、给格式要求，都算提示工程。
- **用来做什么**：零成本、人人可上手地提升输出质量。常见技巧有系统提示词（system prompt）、少样本示例（few-shot，给几个范例照着学）、思维链（chain-of-thought，让它一步步推理）。
- **与其他概念的关系**：只依赖 LLM 本身，是整个「工程方法论」栈的**最内层**——后面讲的 Context Engineering 就是它的进化版。

### 2.2 RAG（检索增强生成）——「开卷考试」

- **是什么**：RAG（Retrieval-Augmented Generation，检索增强生成）= 先从你的资料库里**检索**出相关内容，再让 LLM 参考着这些内容**生成**回答。
- **用来做什么**：解决「模型不了解你的私有数据」和「知识过时」两大痛点——闭卷考试容易瞎编，RAG 就是给它开卷考试。典型场景：企业知识库问答、文档助手、客服机器人。
- **与其他概念的关系**：**RAG = 向量数据库（管检索）+ LLM（管生成）**，这是本图最重要的一条依赖线。同时它是 Context Engineering（决定模型看什么信息）最典型的手段之一。

### 2.3 微调（Fine-tuning）——「送模型去上培训班」

- **是什么**：用自己的数据继续训练一个现成模型，让它在特定领域表现更好。常配合 **LoRA** 等轻量技术，只调一小部分参数，成本低很多。
- **用来做什么**：让「通才」模型变成你要的「专才」——固定口吻、掌握行业术语体系、稳定输出特定格式。
- **与其他概念的关系**：微调改变的是 **LLM 本身**（模型权重），而提示工程和 RAG 都不动模型。与 RAG 怎么选：想让模型「知道新知识」→ 优先 RAG；想让模型「换风格/学套路」→ 考虑微调；实践中常常两者结合。

## 三、智能体：从「会聊天」到「会干活」

前面的概念都还是「你问我答」。**智能体（Agent）** 是让 AI 从「顾问」变成「员工」的关键跃迁。

### 3.1 智能体（Agent）——AI 员工

**智能体 = LLM（大脑）+ 工具调用（手脚）+ 记忆（笔记本）+ 自主规划循环（自己安排做事步骤）**

- **是什么**：能自主拆解任务、选择工具、执行并观察结果、调整计划直到完成目标的 AI 系统。普通 LLM 对话像「问路」——只能告诉你怎么走；智能体像「代驾」——自己规划路线、自己开车、办完事还向你汇报。
- **用来做什么**：自动写周报并群发、监控数据异常并排查、自动订机票酒店、批量处理文件——本站点就是我用一个智能体（WorkBuddy）从零搭建并发布到 GitHub Pages 的。
- **与其他概念的关系**：智能体**依赖** LLM（推理决策）+ 工具调用（执行动作），RAG 和记忆负责给它「补给信息」。它也是理解后面所有产品（Codex、Claude Code、Marvis、WorkBuddy）的钥匙——那些都是智能体思想在不同场景的落地。

### 3.2 工具调用（Tool / Function Calling）——给 AI 装上手

- **是什么**：让模型执行真实动作的机制——开发者预先告诉模型「有哪些工具可用、各需要什么参数」，模型在需要时输出结构化的调用请求，由外部程序真正去执行。
- **用来做什么**：模型本身只会「说话」，工具调用让它能「动手」——查数据库、发邮件、调 API、操作浏览器。
- **与其他概念的关系**：工具调用是**智能体的执行基础**，没有它智能体只能空谈；而 **MCP 是它的标准化封装层**——工具调用解决「能不能动手」，MCP 解决「动手的方式是否统一、可复用」。

### 3.3 MCP（Model Context Protocol）——AI 世界的 USB-C 接口

- **是什么**：Anthropic 在 2024 年底提出的开放协议，2025—2026 年已成为事实行业标准，把「模型连接外部世界」这件事标准化了。以前每个设备一种充电口，MCP 就是「USB-C」——工具按标准封装一次，任何支持 MCP 的模型/智能体都能即插即用。
- **用来做什么**：开发者接入一次工具，全生态通用；用户在智能体产品里「连接」邮箱、GitHub、日历、文档等服务，背后往往就是 MCP。
- **与其他概念的关系**：建立在**工具调用**之上，服务于**智能体**；各种产品里的「连接器/Connector」本质上就是 MCP 思想的同源实现。GitHub、数据库、浏览器、邮件等数以千计的 MCP 服务端已经出现。

## 四、智能体产品与编程助手：地图上的「成品」

抽象概念看完了，来看四款把它们组装起来的代表产品——它们能帮你把「概念」和「实物」对上号。

### 4.1 Codex——OpenAI 的云端编程智能体

- **是什么**：OpenAI 推出的编程智能体（云端 Agent），能接到任务后自主写代码、改代码、跑测试、提交结果。
- **用来做什么**：处理「修一个 bug」「给项目加个功能」这类明确的开发任务；OpenAI 在 2026 年的实践中，3—7 人小团队用 Codex 智能体在五个月内构建了约百万行代码，几乎零行手写。
- **与其他概念的关系**：Codex = **智能体**思想在编程场景的落地，靠**工具调用**读写文件、执行命令；OpenAI 团队还专门写了《Harness Engineering》文章总结驱动它的经验——它是 Harness Engineering（见 5.3）最著名的案例之一。

### 4.2 Claude Code——Anthropic 的终端编程智能体

- **是什么**：Anthropic 推出的命令行编程智能体，住在终端里，能读你的项目代码、改文件、跑命令、做 git 提交，全程向你汇报并等确认。
- **用来做什么**：日常开发提效——重构、写测试、排查报错、解释陌生代码库；因为它直接在项目目录里工作，上下文不需要手动复制粘贴。
- **与其他概念的关系**：同样是**智能体 + 工具调用**的落地。它内置的权限控制、沙箱隔离、日志记录，正是 **Harness** 理念的典型实践（Anthropic 最早把这套方法论系统化）；其负责人那句「我不再逐句写提示词，我设计循环来驱动 Claude」也是 **Loop Engineering**（见 5.4）的注脚。

### 4.3 Marvis——腾讯的操作系统级 AI 助手

- **是什么**：腾讯应用宝团队 2026 年 5 月推出的操作系统级 AI 助手（名字取自「马」+《钢铁侠》AI 管家 Jarvis），采用「1 个主 Agent + 5 个专家 Agent」架构（分别负责文件、系统、应用、浏览器、搜索），有云端（混元/DeepSeek）与本地（Qwen 端侧模型）两种模式。
- **用来做什么**：用自然语言操控整台电脑——「帮我把下载文件夹按类型整理好」「打开浏览器查 XX 并总结」这类指令，它自己拆解步骤、调度对应 Agent 执行，涉及隐私和支付时交回你确认。
- **与其他概念的关系**：Marvis 是**多智能体协作**（主 Agent 拆解任务、副 Agent 分头执行）+ **工具调用**（操控系统、文件、应用）+ **端云结合**（云端大模型 + 本地小模型）的集大成产品；与 Cursor 等「AI 编辑器」的区别在于它管的是整台电脑而不仅是代码。

### 4.4 WorkBuddy——你的个人智能体工作台

- **是什么**：一个面向个人用户的智能体助手产品：模型当大脑，通过「连接器」接入邮箱、GitHub、文档等外部服务，自带记忆（记住你的偏好与项目背景）和定时任务能力。
- **用来做什么**：从零搭建并部署网站、批量处理文件、写好文章后通过邮件连接器发送、每天定时抓取 AI 新闻整理成日报发到 QQ 邮箱——本博客站点正是用它搭建、推送并发布的。
- **与其他概念的关系**：WorkBuddy 是把**智能体**（自主干活）、**MCP/连接器**（标准化工具接入）、**RAG/记忆**（记住上下文）和 **Loop**（定时任务 = 自动触发的循环）打包成开箱即用产品的典型例子——概念地图上的每一层，在它身上都能找到对应物。

> **四款产品怎么区分？** 一句话记忆：**Codex 和 Claude Code 是「程序员搭档」，住在代码里；Marvis 是「电脑管家」，住在操作系统里；WorkBuddy 是「个人工作台」，住在你的日常事务里。** 它们底层都是智能体，差别在于「住在哪儿、管什么」。

## 五、工程方法论：四层工程栈

产品越来越好用，背后是方法论的四次演进。2022—2026 年，AI 工程的关注点从「怎么问」一路升级到「怎么让 Agent 长期自主可靠地干活」，形成了**嵌套**的四层栈（外层包含内层，不是替代）：

```
┌─ Loop Engineering（怎么自动循环运转）────────────┐
│  ┌─ Harness Engineering（怎么安全可靠地执行）──┐ │
│  │  ┌─ Context Engineering（这一轮看到什么）─┐ │ │
│  │  │  ┌─ Prompt Engineering（这句话怎么说）┐│ │ │
│  │  │  └────────────────────────────────────┘│ │ │
│  │  └────────────────────────────────────────┘ │ │
│  └──────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────┘
```

### 5.1 提示工程（Prompt Engineering）——第 1 层：「这句话怎么说」

（详见 2.1）解决「单次对话怎么把话说清楚」的问题，工作单元是一条提示词，持续几秒到几分钟。它是后面所有层的地基——提示词写得含糊，外层再强也救不回来。

### 5.2 Context Engineering（上下文工程）——第 2 层：「这一轮看到什么」

- **是什么**：系统性地设计模型在每次决策前**看到哪些信息**——什么放进去、什么过滤掉、放多少、按什么顺序放。Andrej Karpathy 在 2025 年提出「该从提示工程转向上下文工程」，Anthropic 随后给出了正式定义：策划和维护「最优信息集」的策略。
- **用来做什么**：模型上下文窗口是**有限资源**，塞太多反而「上下文腐烂」（Context Rot）——关键信息被淹没、召回率下降。上下文工程通过 RAG 检索、对话历史压缩摘要、工具列表精简等手段，保证模型每次都看到「最小但最够用」的信息。
- **与其他概念的关系**：是**提示工程的进化版**（前者管「怎么说」，它管「给什么看」）；**RAG、向量数据库、记忆管理**都是它的具体手段；它本身又被 Harness Engineering 包含——在更大的运行环境里被统一编排。

### 5.3 Harness（挽具）与 Harness Engineering（挽具工程）——第 3 层：「在什么环境里干活」

- **是什么**：Harness（直译「马具/挽具」，引申为模型的整套「工作装备」）指包裹在模型外面的所有运行时组件——系统提示词、工具注册与调度、权限控制、沙箱环境、上下文窗口管理、记忆持久化、子 Agent 编排。业界把这条公式挂在嘴边：**Agent = Model + Harness**。Harness Engineering 就是把「裸模型」改造成「能安全干活智能体」的工程实践，2026 年初由 Mitchell Hashimoto（「engineer the harness」）和 OpenAI（用 Codex 百万行代码实践）先后带火。
- **用来做什么**：解决「Agent 演示惊艳、上线拉胯」的问题——不让错误结构性重犯。典型组件：项目规则文件（AGENTS.md/CLAUDE.md，把踩过的坑沉淀成硬约束）、代码检查器与测试门禁（不合格就拦下，而不是「希望」模型遵守）、权限系统（哪些文件能动、能不能联网）、沙箱隔离与可回滚、全程日志观测。一句话：**模型是引擎，Harness 是底盘、变速箱和方向盘**——引擎再强，没有底盘也上不了路。
- **与其他概念的关系**：**包含**上下文工程（信息管线是挽具的一部分）；**被 Loop Engineering 包含**（循环要在挽具提供的安全环境里跑）；Codex、Claude Code、WorkBuddy 等产品里的权限确认、沙箱、审批机制，都是 Harness 的具象。

### 5.4 Loop Engineering（循环工程）——第 4 层：「怎么自动循环运转」

- **是什么**：设计 Agent 的完整迭代循环——**触发条件 → 目标定义 → 行动编排 → 结果验证 → 状态记忆 → 继续/停止**，让工作跨越多轮、持续数小时甚至数天自主推进，而不需要人每次来「点一下火」。2026 年中成为企业 Agent 落地的热门方法论。
- **用来做什么**：把人从「盯→喂→看→下一步」的人肉循环里解放出来。一个可用的 Loop 至少包含：触发器（定时任务、事件监听）、独立执行环境（工作区/worktree）、工具与连接器、子 Agent、持久化记忆与产物、验证与停止条件（预算、验收标准）。你在 WorkBuddy 里建的「每天早上自动抓 AI 新闻、写日报、发 QQ 邮箱」定时任务，就是一个标准的 Loop。
- **与其他概念的关系**：**运行在 Harness 之上**——挽具提供能力，循环自动化执行；没有挽具，循环无处安放；没有循环，挽具只是个等人指令的工具。用开车打比方：Prompt 是方向盘上的指令，Context 是传感器看到的路况，Harness 是整辆车，**Loop 是自动驾驶算法**——决定车怎么在没人干预下从 A 开到 B。

## 六、幕后支撑：向量数据库与推理框架

这两个概念不常出现在新闻标题里，但缺了它们，上面的东西都跑不起来。

### 6.1 向量数据库（Vector Database）——「语义图书馆」

- **是什么**：文本可以经过 **Embedding 模型**转换成一串数字（向量），语义越接近的文本，向量距离越近。向量数据库就是专门存储、检索这些向量的数据库——传统搜索靠「关键词匹配」，它靠「意思相近」：你说「怎么让电脑跑快点」，它能把「清理磁盘垃圾提升性能」的文档也找出来。
- **用来做什么**：支撑一切「按语义找信息」的场景。主流代表：Milvus、Qdrant、Chroma、FAISS，以及 PostgreSQL 的 pgvector 插件。
- **与其他概念的关系**：**向量数据库是 RAG 的检索底座**，同时常被用作智能体的「长期记忆」存储；Embedding 模型（文本→向量）是它的上游依赖。

### 6.2 推理框架（Inference Framework）——「模型的发动机」

- **是什么**：训练好的模型要「跑起来」才能服务用户，负责高效运行模型的软件就叫推理框架。模型是发动机图纸，推理框架是造好的发动机——决定跑多快、烧多少油（显存）、能同时载多少客人（并发）。
- **用来做什么**：把模型变成可用的服务。主流代表：vLLM（高吞吐服务首选）、llama.cpp / Ollama（个人电脑本地跑模型）、SGLang、TensorRT-LLM；配套的**量化（Quantization）**技术还能压缩模型体积，让大模型跑进消费级显卡甚至笔记本。
- **与其他概念的关系**：推理框架在**最底层支撑一切**——不管做 RAG 还是智能体，总得有东西把模型跑起来；开源模型（如 DeepSeek、Qwen、Llama）之所以能被企业自部署，正是「开源权重 + 推理框架」这对组合的功劳。

## 七、角色与组织实践：FDE——把 AI 带到现场的人

### 7.1 FDE（Forward Deployed Engineer，前置部署工程师）

- **是什么**：一种「驻扎在客户/业务现场」的工程师角色，最早由 Palantir 定义并走红，2025—2026 年被 OpenAI、Anthropic 等 AI 公司大量招聘——简单说，就是把 AI 产品**亲手落地**到客户真实业务里的人，一半是工程师，一半是行业顾问。
- **用来做什么**：AI 产品再强，落到具体工厂、医院、银行时总有「最后一公里」问题——数据格式不对、流程对不上、员工不会用。FDE 驻场摸清真实需求，把模型、智能体、工具链裁剪组合成客户能用的方案，跑通后再交回标准产品团队沉淀。本站点的作者目前正在准备食品/烘焙行业 AI 落地方向的 FDE 面试，主打 CV 视觉检测与供应链需求预测——这正是 FDE 工作的典型画像。
- **与其他概念的关系**：FDE 是**把前面所有概念「组装到现场」的人形枢纽**——他要用 Context Engineering 摸清客户的数据，用 Harness/工具调用把方案接进客户系统，用 Loop 把一次性 Demo 变成持续运转的生产流程。理解了整张概念地图，就理解了 FDE 每天在做什么。

## 九、协同工作实例：一次请求的完整旅程

概念单独看都抽象，串起来看就活了。假设你对 WorkBuddy 说：**「总结一下上周 AI 领域的重要新闻，发到我的邮箱」**（这正是一条真实跑通过的定时任务），背后会发生什么——

1. **推理框架**先把 LLM「跑起来」，随时待命（发动机点火）；
2. **智能体**的大脑（LLM）接到任务，规划步骤：先搜集新闻 → 再筛选总结 → 最后发邮件（自主拆解）；
3. 通过 **MCP/连接器**标准接口调用「网页搜索」「RSS 抓取」等**工具**，拿到原始新闻（动手干活）；
4. 需要参考你上周的关注偏好时，从**向量数据库**里语义检索你的历史记录（相当于 RAG 开卷，Context Engineering 在管「看什么」）；
5. LLM 综合所有信息生成日报（**提示工程**决定总结的格式与风格）；
6. 再通过连接器调用「邮件」工具发送，完成后向你汇报（闭环）；
7. 整件事被包在**Harness**的安全护栏里（发邮件前确认收件人、失败可重试），而「每天早上 8 点自动执行」的定时设置，就是**Loop**——你设好循环后，再也不用每天手动点火。

一条指令，二十个概念各司其职。这就是它们协同工作的样子。

## 十、给新手的学习路径建议

按依赖关系自底向上学，事半功倍：

1. **先玩透 LLM 对话**：日常高频使用 ChatGPT / Claude / DeepSeek，练**提示工程**（零成本、见效最快）；
2. **动手搭一次 RAG**：用 Ollama 本地跑个小模型 + 一个向量数据库，做一个「问答自己的文档」玩具，RAG、Embedding、向量检索一次搞懂；
3. **体验智能体产品**：用 WorkBuddy / Marvis 完成一件真实小事，或用 Claude Code / Codex 改一段代码，观察它们如何规划、调用工具、请求权限——你看到的每一步都对应地图上的一个概念；
4. **进阶方法论**：想让自己的 Agent 更可靠，按四层栈逐层加固——先把话说清（Prompt）、再给对信息（Context）、再配好环境（Harness）、最后设好循环（Loop）；
5. **找到自己的位置**：偏工程去研究 MCP 开发、vLLM 服务、微调/LoRA；偏业务可以关注 FDE 这类「AI 落地」角色——它需要的正是把这张地图串起来的能力。

不必追求一次吃透所有细节。记住这张地图的骨架——**LLM 是大脑，工具调用是手脚，MCP 是标准接口，RAG + 向量数据库是记忆与知识，推理框架是发动机，智能体把它们组装成能自主干活的员工；Prompt → Context → Harness → Loop 四层方法论让这个员工越来越可靠；Codex、Claude Code、Marvis、WorkBuddy 是不同场景的成品；而 FDE 是把这一切带进客户现场的人**——以后再看到任何新名词，先问一句「它在地图的哪一层、依赖谁」，就能迅速归位。

祝你在 AI 世界里玩得开心。
